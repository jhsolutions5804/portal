# 7.85. 개발로그 — 전자결재 열람 제한 규칙 본섭 준비 (포털 build 20261001c)

> 2026-10-01 · 춘식이(Claude) · 대표님 지시: "1번부터 하자(edoc 열람 제한 규칙 본섭 게시)" → "다음 거 진행해"

## 배경
- 본섭 규칙에는 테섭에 있던 전자결재 열람 제한이 없어, 승인된 직원이면 남의 전자결재 문서를 읽을 수 있었다.
- 규칙을 넣으면 필터 없는 목록 조회는 일반 직원에게 통째로 거부되므로, 규칙 게시 전에 코드를 먼저 맞춘다(코드는 현행 규칙에서도 동일하게 동작).

## 점검 결과(코드 전수 확인)
| 위치 | 영향 | 조치 |
|---|---|---|
| 전자결재 PC/모바일 목록 | 이미 작성자·viewerUids·posted 기준 | 없음 |
| 포털 홈 결재함 | 일반 결재자는 조회 거부 | 수정 |
| PJT·SUP 연차 구독 | 일반 직원은 연차 전체 거부 | 수정(posted/approved 분리) |
| 인사·모바일 인사 | 관리자 전용 | 없음 |
- 본섭 데이터: 계정 12(관리자 4), 결재선의 일반 직원은 3명. 옛 문서 다수가 viewerUids 없음(업무일지 215/235, 연차 16/25, 구매 12/19, 지출 5/13, 초과근무 4/4) → 작성자·관리자·게시완료만 열람(기존 목록 조회에서도 이미 보이지 않던 문서).

## 검증
- 규칙 변경안 컴파일 확인, 로컬 Firestore 에뮬레이터 14개 시나리오 통과(작성자·결재선·무관 직원·게시완료·관리자·옛 문서·쓰기 유지·필터 없는 목록 거부·PJT 연차 조회·결재함 조회·타 컬렉션 무영향).
- 테섭에는 동일 규칙이 이미 적용돼 있음(코드 build 20261001c 테섭 배포).

## 규칙 변경(본섭, 대표님 콘솔 게시)
- 백업 `backup/rules/20261001_before_edocrules.rules` → `20261001_after_edocrules.rules`. 추가분: `isEdocCollection()`·`canViewEdocDoc()` 함수, `edoc_*` 7종 개별 match, 포괄 규칙에 `!isEdocCollection()`.

## 롤백
- 규칙: before 백업 재게시. 코드: 직전 커밋.

## 알려진 사항
- 일반 직원은 승인만 된(미게시) 연차가 PJT 캘린더에 보이지 않음(의도된 동작).
- 옛 문서에 viewerUids를 채우는 데이터 보정은 하지 않음(별도 결정 사항).
