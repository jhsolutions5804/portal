# 7.90. 개발로그 — 근태 기록(worker_attendance_log) 본인·관리자 한정 규칙 (본섭 반영)

> 2026-10-01 · 춘식이(Claude) · 대표님 지시: "(근태 기록 본인 한정) 지금 여기서 풀자" → 테섭 게시·확인 → "본섭"

## 배경
- 근태 기록은 승인된 일반 직원이면 누구나 서로의 기록을 읽고 쓸 수 있었다(포괄 규칙). 근로자 문서 ID 이전(7_89)으로 ID에서 개인 식별 정보는 사라졌지만, 서로의 출퇴근·근무시간 열람과 변조는 가능했다.

## 규칙(본섭 ruleset 8e350cd5…, 이전 42ef17af…)
- `worker_attendance_log/{근로자ID}_{날짜}`: **관리자 또는 본인**만 읽기·쓰기.
  - 본인 판정 `isAttOwner(workerId)`: 기록의 workerId 에 해당하는 `workers/{workerId}.portalUid` 가 로그인 계정. (portal_users.workerId 는 대부분 계정에 없어 쓰지 않음)
  - 생성: 문서 ID 가 `workerId_date` 이고 workerId 가 본인 근로자. 수정: workerId·date 변경 불가. 삭제: 관리자만(인사 모듈).
  - 월 조회(`where workerId == 본인 AND yearMonth == …`)는 허용, 남의 workerId·조건 없는 목록은 거부.
- 컬렉션을 관리자 전용 목록(`isAdminOnlyCollection`)에 넣어 포괄 규칙에서 제외하고 전용 match 로 처리. 백업 `backup/rules/20261001_{before,after}_attendance_own_only.rules`. 코드·데이터 변경 없음.

## 검증
- 에뮬레이터 30건(출퇴근 저장 merge·월 조회 쿼리·위장 문서 ID·날짜 변경·삭제·게스트·연동 안 된 계정 등) + 변경 전/후 차분(달라지는 컬렉션은 worker_attendance_log 뿐, 관리자 변화 0) + 기획·근로자 민감 문서·근로자 명부 쓰기·인사 캘린더·채용 규칙 회귀 통과.
- 테섭·본섭 실서버(실제 로그인 토큰): 일반 직원 — 본인 월 조회 200(19건)·본인 기록 생성·퇴근 시간 추가 200, 남의 조회·읽기·수정·생성(남의 workerId·위장 ID)·본인 삭제·전체 목록 403. 관리자 — 전체 목록·남의 기록 읽기 200. 시험 기록(2099-01-01) 삭제, 남의 기록 불변, 본섭 근태 기록 171건 그대로.

## 운영상 유의
- 인사에서 근로자 문서와 계정을 연동(portalUid)하지 않은 직원은 출퇴근 기록을 저장할 수 없다 — 새 근로자를 등록하면 계정 연동까지 해야 한다(본섭 근로자 10명은 모두 연동됨). 근로자 문서가 없는 계정(이경택·서민우)은 원래도 근태 기록 대상이 아님.
- 롤백: `before_attendance_own_only.rules` 재게시.
