# 7.63. 개발로그 — 급여명세서 열람 링크·메일 발송 이력·링크/QR (인사 2.17.0)

> 2026-09-30 · 춘식이(Claude) · 대기열 3번 · **portal-test 배포, 본섭 미반영(대표님 확인 대기)**

## 요구
- 문자·메일 기능을 급여명세서에도 적용.

## 구현
- 급여명세서 메일 발송: 기존 링크 방식(72시간, `sign.html`이 **현재 양식(v5)** 으로 재렌더링)의 문제 2가지 개선 — ① 저장 서류 양식 동결 원칙 위반(과거 명세서가 현재 양식으로 표시) ② 72시간 유효기간.
  → 계약서 열람 링크와 같은 **열람 전용 링크**로 통일: 저장 당시 양식(`tplVer`)으로 렌더링한 HTML을 payload에 저장, 180일, 문자 인증 후 열람.
- 카드에 발송 이력 줄(`doc_send_log`, 키=`payslip:<월>`) 및 **🔗 링크·QR (문자/카톡 전달)** 버튼 추가 — 관리자가 링크를 복사해 문자·카카오톡으로 직접 전달.
- 문자 **자동발송**은 미구현: SMS 발송 업체(알리고/솔라피/NHN 등) 계약·API 키와 서버 함수(Cloud Functions) 배포가 필요.

## 검증
- Node vm + 모의 Firestore/EmailJS: 저장양식 v3 → html==v3 렌더러, v0 명세서 → html==v0 렌더러(현재 v5와 다름), status=view, 180일, 모달 문구, 메일 파라미터, 이력 기록·표시.
- 실제 메일 수신·화면은 대표님 테스트 필요.

## 백업

## 정정 (v2.17.1)

- 2.17.0에서 급여명세서 버튼을 모바일형 카드(`psViewWorker`)에만 넣고, **PC 조회 화면(`renderPayslipPCList` → `psLoadWorkerSlips`)에는 빠뜨렸음**(대표님 화면 캡처로 발견). 2.17.1에서 PC 카드에 📧 메일 발송·🔗 링크·QR·발송 이력 줄을 추가. Chromium으로 카드 렌더링 확인.
- 교훈: 같은 문서의 조회 화면이 여러 곳(PC/모바일형)일 수 있으니 저장 문서 렌더 지점을 전부 grep해서 반영할 것.
