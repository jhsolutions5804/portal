**배경**: 지난 세션들에서 본섭에 직접 배포된 패치들이 테섭에 반영되지 않은 게 있는지 확인 요청. 테섭의 마지막 전체 동기화 커밋(2026-07-30) 이후 본섭에서만 163개 커밋이 쌓여 있었음.

**조사**: 커밋 로그 비교 + 실제 파일 내용(키워드/파일크기) 대조로 "진짜 누락된 것"만 선별.
- `pjt`/`pjt_ph4`/`pjt_light`/`pjt_manday`: 근로자 퇴사처리 기능 전체 누락
- `pjt`: 기술인 명단 인라인 수정 누락
- `gihoek`: 정산-견적 연결, 목록 필터, 담당자 tel 버그수정 2건, 인쇄 tel 오표시, 견적 특기사항·품목비고, 공급가액 직접수정, 지급예정서 다중PJT 합산+단가개별수정 등 다수 누락
- (오탐 배제) `pjt`의 주간공정회의/도면매핑, `edoc`의 fetchEdocDocs 스코프수정은 테섭에 이미 반영되어 있었음 — 커밋 메시지만으로 판단하지 않고 실제 코드 대조로 확인

**동기화 방법**: 파일별로 프로덕션 본문 + **테섭 자체 `firebaseConfig`만 유지**한 채 병합(정규식으로 config 블록만 치환). 병합 후 "config를 제외한 나머지 내용이 완전히 동일한지" 재검증.

**대상 파일 (18개)**: `edoc`, `gihoek`, `hr`, `index.html`, `pjt`, `pjt_light`, `pjt_manday`, `pjt_ph4`, `daily-report/data.js`, `m/account·admin·edoc·gihoek·home·hr·pjt·pjt_manday·schedule`

**검증**: `node --check` 문법검증(전 파일 module script), 병합 후 diff로 config 외 완전일치 확인.

**발견된 기존 버그(별도 보고, 이번엔 미수정)**: `pjt/index.html`의 "공사일보 작성" 바로가기가 테섭에서도 여전히 프로덕션 절대주소(`https://jhsolutions5804.github.io/portal/daily-report/`)를 가리킴 — 테섭에서 클릭 시 실제 프로덕션 Firebase에 기록됨. 동기화 이전부터 있던 문제이며 이번 동기화로 새로 생긴 건 아님.

## 작업 3 — 경량 PJT: 일정등록 폼을 메인 PJT(FAB)와 동일하게 개편 (v3.4.0)

**요청**: 메인 PJT와 경량 PJT의 일정등록 화면 스크린샷 첨부, "일정 등록할 때도 다른 프로젝트랑 동일하게 해줘"

**해결**: FAB `pjt/index.html`의 일정등록 로직을 그대로 이식
- 카테고리 9종(반입/검수/교육/회의/설치/안전/휴무/연차/행정) → 8종(교육/회의/반입/설치/휴무/안전/품질/기타), 입력 내용 기반 자동추정 힌트
- 할 일(시간없이 체크리스트) 체크박스 신규
- 시작/종료 시간: 텍스트 입력 → 시/분 드롭다운
- 등록자: 로그인 계정 자동입력
- 구 태그(검수/연차)로 저장된 과거 데이터는 색상 매핑 유지로 계속 정상 표시(하위호환)

**참고로 발견한 점**: 홈 통합캘린더(`index.html`)의 `HOME_SCHED_CATS`는 여전히 구버전 9종을 쓰고 있어, 이미 FAB 개별 모듈과 홈 캘린더 간 태그 체계가 갈라져 있었음. 이번엔 사용자가 보여준 FAB 개별 모듈 기준으로 경량 PJT를 맞춤(홈 캘린더 쪽은 이번 작업 범위 아님).

**진행 순서**: 로컬 구현 → jsdom 실행검증 → portal-test 배포 → 확인 → production 배포(v3.3.0→v3.4.0)
