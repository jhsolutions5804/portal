## 요구
- 기획 > 프로젝트와 PJT관리 > 설정(수정) 어느 쪽에서든 **PJT 코드 · 내용 · 현장명 · 발주처/시공사/협력사**를 동일하게 등록·조회·수정. (Outlook 일정 구분을 PJT명이 아닌 현장명으로 하기 위함)

## 필드 대응
| 항목 | 기획(gihoek_projects) | PJT관리(pjt_registry) |
|---|---|---|
| PJT 코드 | code | name |
| 내용 | name (라벨 '설명'→'내용') | content (라벨 'PJT 내용'→'내용') |
| 현장명 | site (신규) | site |
| 발주처 | client | client (라벨 '거래처'→'발주처') |
| 시공사 | contractor (신규) | contractor (신규) |
| 협력사 | partner (신규) | partner (신규) |

## 동작
- 기획에서 저장 → 연결된(`reg_…`) PJT관리 항목에 6항목을 **저장한 값 그대로(비운 값 포함)** 반영. 신규 '자동 생성'도 6항목 동일 생성 — **기존에 PJT관리 현장명이 발주처 값으로 채워지던 문제 해결**.
- PJT관리에서 저장 → `gihoek_projects`에서 `linkPjt=='reg_<id>'`인 프로젝트를 찾아 6항목 반영. PJT 코드 비우면 저장 거부. 기획 반영이 실패해도 PJT관리 저장은 유지하고 실패를 안내.
- 조회: 기획 상세에 현장명·발주처·시공사·협력사 표시, 목록 보조줄은 '현장명 · 발주처'. PJT관리 기본정보 카드에 PJT 코드·시공사·협력사 추가.
- P4 Ph2(FAB)·P4 Ph4(SUP) 연동 프로젝트는 PJT관리 항목이 없어 **기획에서만** 입력(같은 필드).

- 실제 화면은 대표님 확인 필요.

## 기존 데이터 정리(대표님 확인 필요)
- 현재 본섭 데이터는 두 곳의 값이 다르거나 비어 있음(예: 내용 불일치, 현장명이 발주처 값, 시공사·협력사 없음). 자동으로 덮어쓰지 않고 항목별 확정값을 받아 반영할 것.
