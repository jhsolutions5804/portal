# 7.64. 개발로그 — 문서 메일 수신 주소를 포털 로그인 계정으로 대체 (인사 2.18.0)

> 2026-09-30 · 춘식이(Claude) · 추가 과제 ⑤ · **portal-test 배포, 본섭 미반영**

## 요구
- 직원 메일을 로그인 ID(@jhsol.kr, Outlook) 주소로 발송할 수 있는지.

## 근거 (본섭 데이터 읽기 전용 검증)
- 근로자 명부 10명 ↔ 포털 계정: `portalUid` 연결 10/10, 사원번호(empNo) 1:1 매칭 10/10, 두 방법 결과 일치 10/10, 이름 일치 10/10, 사원번호 중복 없음.
- 명부에 별도 이메일이 등록된 근로자는 1/10 → 기존에는 발송 때마다 주소 입력.
- 명부와 연결되지 않은 계정: guest001(이경택), guest002(서민우) → 수동 입력 유지.

## 구현
- `getRecipientEmailEx(kind, id)`: 명부 이메일 → (근로자) `portalUid` → `portal_users.email`(로그인 ID) 순서로 조회. 발송 전 확인창에 "로그인 계정 주소" 표시. 지원자는 기존과 동일.
- 로그인 계정 주소는 명부(`workers.email`)에 자동 저장하지 않음(입력한 주소만 저장하던 기존 동작 유지).
- 인사 모듈은 관리자 전용이라 `portal_users` 조회 규칙 문제 없음.

## 미확인
- `@jhsol.kr` 주소가 실제 Outlook 사서함인지(테스트 계정 test@jhsol.kr 등은 사서함이 없을 수 있음) — 대표님 확인 필요.

## 검증
- Node vm 모의: 명부 이메일 없음+portalUid → 로그인 주소로 발송·이력(마스킹) 기록, 확인창 문구, 둘 다 없으면 프롬프트 취소 시 미발송.
