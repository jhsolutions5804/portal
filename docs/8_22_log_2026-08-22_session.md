## 작업 3 — 근태 출역 인원수 카운트 버그 수정 (v5.3.5 / daily-report 2.4.2) — 프로덕션 배포 완료

**배경**: 근태 탭에서 "출역 9명 / 전체 5명"처럼 출역 인원이 전체 인원보다 많이 표시되는 걸 대표가 발견. 공사일보 "기술인 투입 현황"도 실제 인원(5명)보다 많은 숫자(9명)로 표시됨.

**1차 진단(수정 후 되돌림)**: 처음엔 "명단에서 삭제된 인원이 화면에 안 보여서 그렇다"고 진단하고 삭제된 인원을 "(삭제됨)"으로 같이 표시하는 기능을 추가했으나, 마스터 명부와 연결 안 된 인원은 이름 복구가 불가능해 전부 "알 수 없음"으로만 뜨는 문제 발견 → 대표 판단으로 이 기능은 되돌림.

**2차 진단(실제 원인)**: `worker_attendance/{날짜}.checks`는 과거 체크 기록을 그대로 보존하는 게 의도된 설계인데, "출역 N명" 배지·공사일보 "투입 현황"이 이 값을 필터링 없이 그대로 써서 명단에서 삭제된 인원의 과거 체크까지 숫자에 포함되고 있었음. 추가로 공사일보는 "전체 인원" 자체를 `data.js`의 하드코딩된 정적 배열(9명 고정)로 계산하고 있어 근태 탭 명단 변경과 무관하게 항상 옛 숫자만 표시하는 별개 버그도 있었음.

**수정**: `pjt/index.html`의 배지/홈 KPI, `daily-report/index.html`의 전체/출역 인원 모두 현재 유효 명단(퇴사일 반영)에 실재하는 ID로 필터링해서 카운트하도록 통일. `daily-report`는 하드코딩 배열 대신 `pjt_workers_fab`+`master_workers` 실시간 조회로 전환.

**검증**: `node --check` → portal-test 배포 → 대표 실 확인("ㅇㅋ 된다") → 프로덕션 배포.

**배포**: `pjt/index.html`(v5.3.5), `daily-report/index.html`(v2.4.2), 버전 코멘트 갱신, 백업(`backup/v5.3.5/pjt/`, `backup/v2.4.2/daily-report/`)
