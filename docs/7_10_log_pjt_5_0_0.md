# 7.10. 개발로그 — PJT 5.0.0 (신규 PJT 자동편입·경량PJT·월간공수·마스터명부)

> 작업일: 2026-07-24 · 작성: 춘식이(Claude)

---

## 배경

기존에는 신규 PJT를 등록해도 PJT 홈 하단에 정보성 카드로만 뜨고, 상단 카드·사이드바 메뉴에는 편입되지 않았음. 근로자 명단도 FAB/SUP/경량PJT가 각자 독립적으로 관리해서, 같은 사람이 여러 PJT를 겸직해도 시스템이 다른 사람으로 인식하는 문제가 있었음.

---

## 주요 변경

### 1. 신규 PJT 자동 편입
- `PJT_SUBTABS` 배열을 하드코딩(P4 Ph2/Ph4)에서 `pjt_registry` 기반 동적 편입으로 확장 (`syncPjtRegistrySubtabs`)
- 신규 항목은 항상 `pjt_manday`(월간공수) 바로 앞에 삽입 → 월간공수 항상 최하단 고정
- 카드 KPI(공정율/D+/누적공수)를 경량 PJT는 `pjt_registry` 필드 직접 참조로 분기 처리

### 2. 경량 PJT 워크스페이스 신설 (`pjt_light/index.html`)
- 파일 하나를 모든 경량 PJT가 `?pjtId=` 파라미터로 공유
- v1(모바일 카드+리스트) → v2(품목체크+근태공수 그리드 추가) → v3(FAB 동일 PC 대시보드 레이아웃, 일정관리를 캘린더로 전면 개편, 일정 상세/수정, 인원별 누적공수)까지 3단계 반복 개선
- 버그 수정: 캘린더 재렌더 시 빈 셀 누적으로 레이아웃 밀리는 문제, 공수 저장이 출역체크에 의존하던 문제

### 3. 근로자 마스터 명부 (`master_workers` 컬렉션)
- 이름+생년월일을 고유 식별 코드로 사용, 팀장-팀원 1단계 트리 구조, 일당(관리자 전용)
- 기존 인원(FAB 9명·SUP 1명·경량PJT 각각) 마이그레이션 도구: 이름으로 그룹핑 → 생년월일 입력 → 마스터 등록. 마스터ID는 최초 발견 프로젝트의 로컬ID를 재사용해 과거 이력 보존
- FAB/SUP/경량PJT의 "인원 추가"를 텍스트 입력 → 마스터 명부 선택 방식으로 전환. 이후 신규 등록되는 워커 문서는 마스터ID를 그대로 문서ID로 사용 → 사후 매칭 없이 자동 통합

### 4. 월간 공수 집계 (`pjt_manday/index.html`, 신규)
- PJT별/개인별/팀별 합계, 개인별 통합 공수표(캘린더+PNG저장)
- **중대 오진단 정정**: 최초 설계 시 FAB·SUP가 `worker_manday`/`worker_attendance`를 공유한다고 가정했으나, 실제로는 SUP가 `ph4_manday`/`ph4_attendance`라는 별도 컬렉션을 쓰고 있었음. 이 때문에 SUP 공수가 한동안 집계에서 완전히 누락되는 버그가 있었고, 디버그 패널로 원본 데이터를 직접 대조해 발견·수정함

### 5. 부수 버그 수정
- FAB/SUP 근태 화면이 모듈변수(`WORKERS`) 캐시에 의존해, 근로자 명단 갱신 후에도 화면이 예전 상태로 남던 문제 → `renderWorkerList`가 `getWorkers()`를 직접 호출하도록 근본 수정
- SUP의 "전체 출역 일괄" 버튼이 실수로 `worker_attendance`(FAB 컬렉션)에 저장하던 버그 → `ph4_attendance`로 통일
- `openModule()`의 URL 쿼리 결합 로직이 `?pjtId=`처럼 이미 쿼리스트링이 있는 URL에서 깨지던 문제 수정

### 6. 안전조치
- portal-test의 FAB/SUP가 그동안 **프로덕션 Firebase 프로젝트를 그대로 바라보고 있던** 문제 발견 → `portal-test-6e0ff`로 분리 (테스트 데이터가 실 데이터에 영향 주던 리스크 해소)
- 진단용으로 FAB/SUP 화면에 임시로 노출했던 디버그 뱃지(Firebase 프로젝트/근로자 명단 텍스트)는 **프로덕션 배포 전 완전히 제거**
