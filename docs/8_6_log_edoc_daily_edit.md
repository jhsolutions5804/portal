# 8_6 · 전자결재 업무일지 임시저장/반려 상태 수정 기능 (r1)

**작업일**: 2026-07-20
**대상**: `edoc/index.html`
**요청 계기**: 대표님 — "업무일지 상신했다가 회수하면 임시저장 상태로 돌아가는데, 임시저장 상태에서 수정 가능하게 기능 추가"

## 배경 (원인 분석)
- 업무일지 상세화면(`renderDailyDetail`)에는 애초에 "수정" 버튼 자체가 없었음 (회수·삭제 버튼만 존재)
- 작성화면(`renderDailyWrite`)도 항상 신규 등록(`addDoc`)만 지원 → 회수로 `draft`(임시저장) 상태가 되어도 새 문서를 또 만드는 것 외엔 방법이 없었음
- `canEdit`(작성자 본인 + `status==='draft'`이거나 `'rejected'`) 조건은 이미 코드에 계산돼 있었지만 실제로 쓰이지 않고 있었음 — 버튼만 추가하면 되는 상황이었음

## 수정 내용
- `renderDailyDetail`: `canEdit` 조건 충족 시 "✏️ 수정" 버튼 노출, 클릭 시 `renderDailyWrite(d)` 호출(기존 문서 전체 전달)
- `renderDailyWrite(existingDoc)`: 인자로 기존 문서가 오면 제목·일자·프로젝트·소속/직급/이름·오늘업무·내일업무·이슈를 모두 미리 채운 "수정" 모드로 렌더 (헤더에 "임시저장 상태 수정 중" 배지 표시, 뒤로가기 시 상세화면 복귀). 인자 없이 호출(기존 "✏️ 작성" 버튼)하면 기존과 동일하게 신규 작성
- `dailySave(status)`: `window._dailyEditId`(수정 대상 문서 id)가 설정돼 있으면 `setDoc(..., {merge:true})`로 기존 문서를 덮어씀(중복 문서 생성 방지), 없으면 기존처럼 `addDoc`으로 신규 등록. 수정 시 최초 `createdAt`은 보존하고 `updatedAt`만 추가 기록. 저장 성공 후 `_dailyEditId` 초기화

## 검증
- `node --check`(모듈 import 구문 제거 후) 전체 script 블록 문법 오류 없음 확인
- 기존 "✏️ 작성" 버튼(무인자 호출)과 하위호환 확인 — 신규 작성 흐름 영향 없음
- 따옴표 등 특수문자 포함 데이터의 onclick 속성 이스케이프 정상 동작 확인(기존 `printDocA4` 버튼과 동일한 이스케이프 패턴 재사용)
- 다른 문서유형(연차·초과근로·구매품의 등)과 로직이 완전히 분리되어 있어 영향 없음 확인
