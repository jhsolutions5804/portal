# 8_5 · PJT 일정 자정 넘기는 일정 시작일 표시 (r1)

**작업일**: 2026-07-20
**대상**: `pjt/index.html`(FAB) · `pjt_ph4/index.html`(SUP)
**요청 계기**: 대표님 — "PJT 일정에서 날이 넘어가는 경우 (7/20 19:00 ~ 7/21 05:00) 7/20에만 일정이 표시되고 7/21에는 표시되지 않게"

## 배경
- `user_schedules`(FAB)/`ph4_schedules`(SUP)는 `sdate`/`edate`로 다중일 지원. 기존 `_usItemsForKey`는 `sdate`≠`edate`인 모든 일정을 시작일(start)~중간일(mid)~종료일(end)로 매일 렌더
- 저녁에 시작해 자정을 넘겨 새벽에 끝나는 일정(예: 19:00~05:00)도 동일 로직으로 처리되어 다음날에도 중복 노출되는 문제 발생

## 확인 사항 (사용자 확답)
- 3박4일 출장처럼 진짜 여러 날짜에 걸친 일정은 지금처럼 각 날짜에 계속 표시하고, "저녁~다음날 새벽"류 자정 넘김 일정만 시작일에만 표시하는 것으로 확정

## 수정 내용
- `_usItemsForKey`(일정 목록 필터링 함수)에 자정 넘김 판별 로직 추가:
  - 조건: `isTodo`가 아니고, 종료일이 시작일의 정확히 다음날(diff=1)이고, 종료시각(`etime`) ≤ 시작시각(`stime`)
  - 위 조건 충족 시 필터링/렌더링용 종료일(`ed`)만 시작일과 동일하게 압축 → 시작일에서만 매치되어 표시
  - 원본 종료일(`rawEd`)은 push되는 객체의 `_ed`에 그대로 보존 → 상세보기(`openUsDetail`/`_usRangeText`)·수정(`_detailEdit`)에서는 정확한 원본 종료일·시간이 유지됨
- FAB(`pjt/index.html`)·SUP(`pjt_ph4/index.html`) 완전 동일 로직 적용
- 모바일(`m/pjt.html`)은 애초에 `edate` 기반 다중일 렌더링이 없어(하루짜리 `sdate` 기준으로만 표시) 해당 없음, 수정 불필요

## 검증
- 단위 테스트(node) 6개 시나리오 전부 통과:
  - 19:00~05:00 자정넘김 → 시작일만 표시, 다음날 미표시 (요청 사항 정확히 재현)
  - 3박4일 출장(09:00~18:00, 종료>시작) → 기존대로 start/mid/end 각 날짜 표시 유지
  - 2일 컨퍼런스(09:00~18:00, 자정 안넘김) → 기존대로 유지
  - 동일시각 엣지(19:00~19:00) → 자정넘김으로 처리, 시작일만 표시
  - 단일일 일정 → 변화 없음
  - Todo 항목 → 자정넘김 판별 대상 제외(기존 로직 유지)
- `node --check`: FAB·SUP 두 파일 전체 script 블록 문법 오류 없음 확인
