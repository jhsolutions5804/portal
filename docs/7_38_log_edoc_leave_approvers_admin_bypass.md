# 연차신청서 결재라인(approvers) 추가 + 관리자 결재함 전체조회 (2026-09-16)

> 작성: 춘식이(Claude)

## 요청
대표님 — "다른 사람들은 자기 결재 순서에 맞게 보이면 되고, 나는 관리자 계정이니까 다 보이는 게 좋다."

## 배경
지난 세션에서 진단한 문제: `DOC_CONFIG.leave`에 `approvers`가 없어 결재라인 자체가 생성되지 않고, 그래서 결재대기 상태여도 누구의 결재함에도 뜨지 않았음.

## 수정
`edoc/index.html`
1. `DOC_CONFIG.leave`에 `approvers:['김종화']` 추가 — 다른 문서종류(초과근로·재직증명서·구매품의서·지출결의서 = 김종화, 퇴직원서 = 김종화·김영희·송지훈)와 동일 패턴. 이제 연차 제출 시 정상적인 결재라인이 생성되어, 결재자 본인 순서에 approvalLine이 매칭되면 결재함에 노출됨(일반 흐름).
2. `loadApproveData`에 관리자 예외 추가: 결재라인에 실제로 uid가 걸려 있지 않은 문서라도(approvers 미지정으로 저장된 과거 연차 등) 관리자 계정에게는 `status`가 `pending`/`reviewing`이면 무조건 결재함에 노출. 일반 직원의 "자기 순서에 맞을 때만" 로직은 그대로 유지.

## 검증
- JS 구문(`node --check`) 통과 — production/portal-test 두 파일.
- 두 파일 diff가 Firebase 설정 외 완전 동일함을 확인 후 각 레포 원본에 동일 패치 독립 적용.

## 배포
대표님 지시("ㅇㅇ") 따라 production + portal-test `edoc/index.html` 동시 배포. 버전 4.2.0 → 4.3.0.

## 참고
approvers 미지정으로 이미 생성된 기존 연차신청서(결재라인에 결재 단계 없음)는 이번 수정으로 관리자 결재함에는 뜨지만, 정식 결재 단계가 없으므로 일반 결재 흐름(승인/반려)이 아니라 관리자가 직접 확인 후 게시 처리하는 방식으로 처리하시면 됩니다. 이번 수정 이후 신규로 작성되는 연차신청서부터는 정상적인 결재라인(김종화)이 생성됩니다.
