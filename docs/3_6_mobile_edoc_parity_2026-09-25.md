# 3.6. 전자결재 — 모바일·PC 기능 동일화 및 개편 (2026-09-25)

> 대상 파일: `m/home.html`, `m/edoc.html`, `m/admin.html`, `edoc/index.html`
> 작성일: 2026-09-25 · 작성: 춘식이(Claude) · 릴리스: edoc module v4.9.0 / 모바일 홈 v2.8.3 / 모바일 관리 v2.8.0

---

## 배경

모바일 `m/edoc.html`이 PC `edoc/index.html`과 상당히 다른(더 단순한) 구현으로 따로 존재해 왔음. 김짜장 요청으로 하루 세션에 걸쳐 모바일을 PC와 동일한 수준으로 맞추고, 그 과정에서 발견된 버그·설계 변경을 함께 반영함.

## 1. 모바일 홈 (`m/home.html`)

- 최상단 원탭 출퇴근 카드 신설: 출근하기 → 근무 중(실시간 타이머) → 퇴근하기 → 오늘 근무 완료. `worker_attendance_log`에 자동 기록, 수정은 전자결재 출퇴근 기록 탭에서.
- 근무자 명부 미매칭 계정(관리자 등)은 `staff_{uid}` 폴백으로 워커ID를 대체 부여 — 출퇴근 카드·출퇴근 기록 탭 모두 이용 가능(당초 "미연동 계정 숨김" 방침에서 변경).
- 개별 PJT 카드(FAB/SUP/경량 프로젝트) 나열 제거 → "PJT 관리" 단일 진입점(`pjt.html`)으로 축소. `pjt_registry` 구독 자체는 오늘 일정 뱃지 카운트를 위해 유지.
- "더보기"에 회사내규 열람 타일 추가(4열→5열), `m/admin.html?v=rules`로 연결.

## 2. 회사내규 열람 (`m/admin.html?v=rules`, 신규)

- PC `index.html`의 내규 열람 기능(`company_policies` 컬렉션, `order` 정렬, 탭 전환, 마크다운 렌더러)을 이식.
- ⚠️ 2026-09-25 기준 `company_policies` 컬렉션에 등록된 문서가 없음(PC도 동일 상태) — 데이터 입력 필요.

## 3. 업무일지 (`edoc_daily`) — 모바일 전면 개편

- 프로젝트 선택(`gihoek_projects`, status≠done) 추가, 선택 시 제목 자동생성(`(코드) yymmdd 이름 업무일지`).
- 임시저장/상신 분리, 임시·반려 문서 수정 지원, 상신 후 회수(→ draft) 지원.
- `viewerUids`에 관리자가 "업무일지 권한관리"에서 지정한 `dailyViewTargets`를 병합 — 기존엔 결재라인 3명만 포함되어 모바일에서 작성 시 추가 열람권자가 못 보는 버그가 있었음.
- 결재라인 김종화님 직급을 **부사장**으로 통일(PC 기준, `portal_users` 실제 데이터로 확인).
- 캘린더 뷰 신설(PC 3.1 r6와 동일 컨셉): 월 캘린더 기본 진입, 날짜별 작성 건수 점 표시, 날짜 탭 시 그날 것만 표시, "전체목록" 토글로 기존 리스트도 유지, 캘린더에서 날짜 지정 후 바로 작성 가능.

## 4. 연차신청서 (`edoc_leave`) — 모바일 전면 개편

- 휴가 종류를 PC와 동일한 11종으로 교체(연차(유급)/반차-오전·오후/생리/출산전후/배우자출산/유산·사산/육아휴직/가족돌봄/병가/예비군·민방위).
- 제목·일수 자동생성(반차류 0.5일, 그 외 평일수 계산), 비상연락처(전화번호 자동 포맷), 업무 대리인(회람) 선택 추가.
- 결재 방식을 PC와 동일하게 변경: 기존 "김종화 고정 1인 결재" → **결재1(작성자가 전 직원 중 직접 지정) + 결재2(김종화 부사장 고정) + 회람(업무대리인, 선택 시)**.
- title 필드 누락 버그 수정: 기존 모바일 저장 로직이 title을 아예 저장하지 않아 PC에서 "(제목없음)"으로 보이던 문제 — 본섭 `edoc_leave` 25건 중 8건(전부 모바일 작성분)이 해당. 신규 작성분부터 자동 해결, 기존 8건은 데이터 backfill 필요(미실행, 김짜장 확인 대기 중이었음 — 본 배포에는 포함 안 됨).
- 임시저장/수정/회수, 이미 결재된 문서는 "관리자 정정 저장"(결재상태 유지) 지원.
- 캘린더 뷰 신설(PC와 동일): 전 직원 연차가 날짜별 표시(승인·게시=파랑, 결재대기=주황), 날짜 탭 시 그날 연차 쓴 사람 명단 팝업, 개인 연차 부여/사용/잔여 카드(`calcAnnualLeaveGrant`/`sumLeaveUsed` 계산식 그대로 이식).
- `canApprove` 결재 역할 매칭을 `/^결재/` 접두어 방식으로 일반화 — `결재1`/`결재2` 등 다단계 결재를 인식하도록 수정(기존엔 정확히 `'결재'` 문자열만 인식해 연차 2단계 결재가 승인 버튼에 안 잡혔음).

## 5. 퇴직원서 · 재직증명서 · 구매품의서 · 지출결의서 (모바일)

- 퇴직원서·재직증명서: 기존 "준비 중" 스텁을 PC `DOC_CONFIG` 기반 실제 작성/조회 화면으로 구현.
- 구매품의서·지출결의서: 결재자 하드코딩(김종화 차장 고정) → PC와 동일한 `DOC_CONFIG.approvers/cc` 기반 결재선으로 교체. 제목 자동생성 추가.
- 4종 모두 `MOBILE_DOC_CONFIG` 단일 정의(필드/결재선)로 통합, 제네릭 작성/목록/상세 렌더러 사용 — PC의 `DOC_CONFIG`+`renderDocWrite`/`docSave` 패턴과 동일한 구조.

## 6. 인사카드 (모바일 신규)

- PC `renderMyCard`와 동일: 로그인 계정 본인의 근무자 명부 정보만 읽기 전용 조회(`_myRealWorkerId` 매칭, 주민등록번호·계좌번호는 마스킹).

## 7. 출퇴근 기록 — 지난 날짜 수정 지원 (PC + 모바일)

- 기존엔 PC·모바일 모두 **오늘 날짜만 수정 가능**, 월별 상세 내역은 조회 전용이었음(의도된 제약이었으나 김짜장이 개선 요청).
- 편집 카드를 날짜 독립적으로 일반화(`attLoadEditCard`/`attLoadEditCardM`) — 월별 상세 내역의 각 행을 클릭하면 그 날짜 기록이 편집 카드로 로드되어 수정·저장 가능. 오늘이 아닌 날짜 편집 중엔 "오늘로" 버튼으로 복귀.
- `3_5_edoc_attendance_mycard.md`의 "오늘 날짜만 기록 가능(의도된 제약)" 서술은 본 변경으로 더 이상 유효하지 않음 — 과거 날짜도 본인이 직접 수정 가능.

## 8. 초과근로 결재 — 완전 제거 (PC + 모바일)

- 김짜장 결정: 초과근로 수당은 결재 절차 없이 **출퇴근 기록만으로 관리**.
- PC: `EDOC_TABS`/사이드바/탭바/탭콘텐츠, `renderOvertimeMain`/`Write`/`Save`, 통상임금 계산 헬퍼(`otCalcAnnualSalary`/`otLoadWorkers`/`otGetWage`), `DOC_CONFIG.overtime`, 결재함 `DOC_TYPES`, 승인 시 "인사 `overtime` 컬렉션 자동 등록" 연동 로직 전부 제거.
- 모바일: 홈 메뉴 타일, `render()` 맵, 결재함 통합리스트/필터/카드, `edoc_overtime` 구독, 동일한 자동연동 로직 제거.
- 인사 모듈(`hr/index.html`)의 `overtime` 컬렉션 직접 관리 기능(근로시간 탭, 통상임금 자동계산 포함)은 그대로 유지 — 필요 시 인사에서 수기 입력. → `3_4_edoc_overtime_r1.md`는 REMOVED 처리, 본 문서로 대체.

## 9. 결재함 — 필터 신설 (PC + 모바일)

- 기존 PC의 "결재대기/결재완료" 2탭 방식과 모바일의 무필터 통합리스트를 모두 걷어내고, **결재 단계(전체/결재중/결재완료/반려) + 서류 종류 + 작성자** 3종 셀렉트 필터로 통일.
- PC `fetchEdocDocs` 대상에 `overtime`이 있었으나 8번 항목으로 제거되어 현재 대상: `daily, leave, resign, cert, purchase, expense`.

## 10. 권한/열람 범위 버그 수정

- 모바일 `sub()` 구독 함수가 관리자가 아닌 사용자에겐 `authorUid`(본인) + `viewerUids`(내가 결재라인에 포함된 것)만 조회하고, **게시(posted) 확정 문서를 전 직원에게 열람시키는 조회가 빠져 있었음**(PC `fetchEdocDocs`는 처음부터 포함). 연차 달력처럼 "전 직원 게시 문서를 봐야 하는" 기능이 제대로 작동하려면 필수라 이번에 추가.
