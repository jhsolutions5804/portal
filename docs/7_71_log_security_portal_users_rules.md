# 7.71. 개발로그 — 보안: 계정 문서(portal_users) 규칙 보강 (1단계)

> 2026-09-30 · 춘식이(Claude) · 배포: **테섭 게시 완료 / 본섭 미게시**

## 발견 경위
팀장 공수표(팀장 계정별 자기 팀 조회) 설계 중 “팀장이 스스로 팀장 연결을 바꿀 수 없다”는 규칙 테스트가 실패해 조사.

## 문제
- 포괄 규칙 `match /{document=**} { allow read, write: if isApproved() && !isAdminOnlyCollection(); }`가 `portal_users`에도 적용됨. Firestore 규칙은 일치하는 match 중 하나라도 허용하면 허용(OR)이라, `portal_users` 전용 규칙(“쓰기는 관리자만”)이 무력화됨.
- 승인된 직원 계정이면 누구나: ① 다른 직원·관리자 계정 문서 읽기(`_pw` = 비밀번호를 base64로만 감싼 값 포함) ② 본인 계정에 `admin:true` 쓰기(스스로 관리자 승격) ③ 다른 직원 계정의 `status` 등 변경.
- 승격하면 `master_worker_private`(주민번호·계좌·검진·포털 ID/PW)까지 읽힘 → 앞서 문서에 적은 “관리자 전용 문서라 안전” 표현은 부정확했음(정정).
- 본섭 규칙(2026-09-30 06:52 게시본)도 동일 구조임을 읽기 전용으로 확인. 회사 계정이 필요한 내부 위협이며 악용 여부는 확인 불가.

## 1단계 조치 (규칙)
- `portal_users`를 포괄 규칙 제외 목록에 추가하고 전용 규칙 정리: 읽기(승인 직원·본인), 쓰기(관리자), 본인 수정은 `_pw`·`phone`·`phoneVerified`·`phoneVerifiedAt` 4개 필드만, 부트스트랩 규칙 유지.
- 앱의 직원 본인 쓰기 지점을 코드 전수 조사(본섭 28개 파일)해 예외 범위를 산정: 비밀번호 변경, 내 정보 전화번호, 휴대폰 인증 표시. 그 외 쓰기(권한 칩·직급·사번·계정 생성·인사 연동·일지 열람 권한관리)는 모두 관리자 화면.
- `dailyViewTargets`는 처음엔 본인 예외에 넣었으나(관리자 화면 전용임을 확인하고) 본인이 열람 범위를 넓힐 수 있어 제외.
- 에뮬레이터 검증: 본섭용 29·테섭용 32항목 통과(정상 동작 유지 / 스스로 승격·권한 변경·남의 계정 수정·임의 계정 생성 차단 / 부트스트랩 / 팀장 단가 범위 / 기타 컬렉션 회귀).

## 배포
- 테섭 Firestore 규칙 게시(이전 규칙셋 `32239773…` → `e85ffec2…`), 게시본과 보강안 일치 확인. 롤백은 보관된 원본으로.
- 규칙 파일·원본 보관: portal-test `backup/firestore_rules_20260930_portal_users_fix/`.

## 남은 위험 (2단계 예정)
- `_pw`가 승인된 직원에게 여전히 읽힘(관리자 계정 포함) → 비밀번호를 본인·관리자만 읽는 별도 문서로 이동(앱 수정 + 기존 값 이전), 궁극적으로는 저장하지 않는 재설정 방식 권장.
- 그 사이 관리자 비밀번호 변경 권장.
