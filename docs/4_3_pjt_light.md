## 접근 검증 (2026-07-27)

- 기존엔 Firebase Auth가 없어 URL(`.../pjt_light/?pjtId=...`)로 직접 열면 로그인 여부와 무관하게 노출됐고, 관리자 여부도 `?admin=1` 파라미터로 판단해 URL 조작만으로 편집 권한이 노출될 수 있었음
- pjt_manday와 동일한 단일 진입점(`init()`) 구조라, 로그인+`portal_users` 검증(`status==='approved' && (admin || perms.pjt)`) 통과 후에만 `init()`을 호출하도록 수정. `isAdmin`도 실제 `portal_users.admin` 값으로 전환

## 개요

FAB/SUP처럼 대규모 zone 기반 시스템이 필요 없는 소규모 신규 프로젝트(예: 화성 17L)를 위한 공용 워크스페이스 템플릿. **파일 하나(`portal/pjt_light/index.html`)를 모든 경량 PJT가 공유**하며, URL 쿼리파라미터 `?pjtId={pjt_registry 문서ID}`로 프로젝트를 구분한다.

- 신규 파일을 만들지 않아도 되므로 PJT 홈에서 "신규 PJT 등록"만 하면 워크스페이스가 자동 연결됨
- 관리자 여부는 포털 `openModule()`이 자동으로 붙여주는 URL `&admin=1` 파라미터로 판별

## 탭 구성 (FAB/SUP와 동일한 UI 언어)

| 탭 | 내용 |
|----|------|

| 📦 품목현황 | 장비별(예: FCU-1, FCU-2) 공정 단계 체크그리드. 단계 목록은 홈 탭에서 자유 설정(기본값: 반입·설치·시운전). **일괄 등록/수정(v3.3.0)**: 붙여넣기로 여러 품목 한번에 추가 + 기존 품목 이름수정·삭제를 목록에서 한 번에 저장 |

| 📅 일정관리 | 월간 캘린더 + 날짜별 상세 패널. PJT 홈 통합캘린더와 동일한 필드 구조(카테고리칩·시작종료일시·장소·참석자·등록자) 사용 → 양방향 연동 |

## 진행률(공정율) 자동 계산

- `pjt_registry/{id}/items/{itemId}` = `{name, stages:{단계명:true/false}}`
- 공정율 = (체크된 셀 수) ÷ (품목 수 × 단계 수) × 100 → 체크 시마다 `pjt_registry/{id}.progress` 필드에 자동 저장 (`recalcProgress`)
- PJT 홈 카드의 "공정율" KPI가 이 값을 그대로 표시

---

## 근태·공수

- 근로자는 **마스터 명부(4.4 참조)에서 선택**해서 추가. 로컬에서 새로 이름 입력하는 방식 아님
- 선택 시 `pjt_registry/{id}/workers/{masterId}` 문서를 **마스터 ID를 그대로 문서ID로** 생성 → 여러 PJT에 걸친 동일 인물 자동 식별
- `pjt_registry/{id}/attendance/{dateKey}` = `{checks:[workerId,...]}`, `pjt_registry/{id}/manday/{dateKey}` = `{md:{workerId:공수}}`
- **출역 체크와 공수 입력은 서로 독립** — 체크 안 해도 공수 숫자만 입력하면 저장됨 (이전 버전 버그: 체크 안 하면 공수도 저장 안 되던 문제 수정됨)
- 저장 시 `pjt_registry/{id}.manday` 필드에 전체 누적공수 자동 갱신(`recalcTotalManday`)

## 일정관리 (캘린더)

- 월간 그리드(좌) + 날짜별 상세(우), FAB 앱의 캘린더 탭과 동일한 시각 언어
- 필드: `sdate`/`edate`/`stime`/`etime`/`tag`/`tagLabel`/`text`/`place`/`att`/`reg` — **PJT 홈 통합캘린더(4.0)와 완전 동일한 스키마** → 상호 조회·수정·삭제 가능
- 태그 9종(반입/검수/교육/회의/설치/안전/휴무/연차/행정)은 홈 통합캘린더의 `HOME_SCHED_CATS`와 동일한 값 사용
- 상세보기 → 수정/삭제 가능 (v3.1 이전엔 삭제만 가능했음)

## PC/모바일 반응형

- 기본은 모바일 카드형(최대폭 640px), `@media (min-width:900px)`에서 FAB/SUP와 동일한 PC 대시보드로 전환

## v3.3.0 변경 요약 (2026-08-20) — 공사일보 고도화 + 품목현황 일괄 등록/수정

### 공사일보 (메인 PJT 수준으로 고도화)
- **작성자**: 자유입력 → `portal_users` 컬렉션 기반 드롭다운(이름+직급) + 로그인 계정 자동 선택
- **금일 작업내용 자동반영**: 품목현황 탭에서 그날 체크한 품목·단계를 자동 문장화. 이를 위해 `toggleItemStage`가 체크/해제 시 `pjt_registry/{id}/item_checks/{날짜}` 서브컬렉션에도 날짜별 로그를 남기도록 수정 (기존 `items.stages` 구조는 그대로 유지, 신규 서브컬렉션만 추가)
- **명일 예정 작업** 필드 신규
- **투입 인원 · 공수**: 근태·공수 탭의 `attendance/{날짜}.checks.length`(인원)와 `manday/{날짜}.md` 합계(공수, 인원수로 나눈 1인당 평균으로 자동 환산)를 자동 반영. 화면엔 `인원 × 공수 = 합계 투입공수` 형태로 실시간 계산 표시, 저장 시 `headcount`/`manday`/`mandayTotal` 3개 필드 모두 저장
- **사용 장비**: 칩 선택 UI (지게차 목록, FAB과 동일 자산 목록)
- **미리보기 · PDF저장**: 인쇄용 문서 레이아웃 생성 후 `window.print()`
- **조회/수정/삭제**: "전체보기" 버튼 → 누적 목록 모달 → 클릭 시 상세보기 모달에서 수정·삭제·PDF 가능 (기존엔 조회 자체가 불가능했음)
- 저장 필드: `date`/`site`/`author`/`content`/`tomorrow`/`headcount`/`manday`/`mandayTotal`/`equip`/`note` — 기존 `content`/`note` 필드명은 하위호환 유지

### 품목현황 일괄 등록/수정
- "📋 일괄 등록/수정" 버튼(관리자 전용) → 모달
  - **붙여넣기 일괄 추가**: 텍스트박스에 품목명을 한 줄에 하나씩 붙여넣고 추가 → `writeBatch`로 한번에 등록 (순수 추가, 기존 항목 영향 없음)
  - **기존 품목 수정·삭제**: 현재 품목 전체를 목록으로 표시, 이름 수정 또는 삭제 표시 후 "수정사항 저장"으로 한번에 반영. **문서 ID 기준으로 매칭**하므로 이름을 바꿔도 기존 `stages`(공정 체크 상태)는 보존됨. 삭제는 실행 전 확인창 표시

### 검증 방식
- `node --check`로 module script 문법 검증
- HTML의 모든 `onclick`/`onchange` 참조 함수가 실제 정의되어 있는지 정적 검증
- jsdom + 인메모리 모의 Firestore(writeBatch 포함)로 실제 로직 실행 검증: 자동반영/저장/조회/수정/삭제/장비칩/일괄추가/일괄수정삭제/인원×공수 계산 전체 케이스 통과 확인
