## 접근 검증 (2026-07-27)

- 기존엔 Firebase Auth가 없어 URL(`.../pjt_light/?pjtId=...`)로 직접 열면 로그인 여부와 무관하게 노출됐고, 관리자 여부도 `?admin=1` 파라미터로 판단해 URL 조작만으로 편집 권한이 노출될 수 있었음
- pjt_manday와 동일한 단일 진입점(`init()`) 구조라, 로그인+`portal_users` 검증(`status==='approved' && (admin || perms.pjt)`) 통과 후에만 `init()`을 호출하도록 수정. `isAdmin`도 실제 `portal_users.admin` 값으로 전환

## 개요

FAB/SUP처럼 대규모 zone 기반 시스템이 필요 없는 소규모 신규 프로젝트(예: 화성 17L)를 위한 공용 워크스페이스 템플릿. **파일 하나(`portal/pjt_light/index.html`)를 모든 경량 PJT가 공유**하며, URL 쿼리파라미터 `?pjtId={pjt_registry 문서ID}`로 프로젝트를 구분한다.

- 신규 파일을 만들지 않아도 되므로 PJT 홈에서 "신규 PJT 등록"만 하면 워크스페이스가 자동 연결됨
- 관리자 여부는 포털 `openModule()`이 자동으로 붙여주는 URL `&admin=1` 파라미터로 판별

## 진행률(공정율) 자동 계산

- `pjt_registry/{id}/items/{itemId}` = `{name, stages:{단계명:true/false}}`
- 공정율 = (체크된 셀 수) ÷ (품목 수 × 단계 수) × 100 → 체크 시마다 `pjt_registry/{id}.progress` 필드에 자동 저장 (`recalcProgress`)
- PJT 홈 카드의 "공정율" KPI가 이 값을 그대로 표시

---

## 근태·공수

- 근로자는 **마스터 명부(4.4 참조)에서 선택**해서 추가. 로컬에서 새로 이름 입력하는 방식 아님
- 선택 시 `pjt_registry/{id}/workers/{masterId}` 문서를 **마스터 ID를 그대로 문서ID로** 생성 → 여러 PJT에 걸친 동일 인물 자동 식별
- `pjt_registry/{id}/attendance/{dateKey}` = `{checks:[workerId,...]}`, `pjt_registry/{id}/manday/{dateKey}` = `{md:{workerId:공수}}`
- **출역 체크와 공수 입력은 서로 독립** — 체크 안 해도 공수 숫자만 입력하면 저장됨 (이전 버전 버그: 체크 안 하면 공수도 저장 안 되던 문제 수정됨)
- 저장 시 `pjt_registry/{id}.manday` 필드에 전체 누적공수 자동 갱신(`recalcTotalManday`)

---

## 일정관리 (캘린더)

- 월간 그리드(좌) + 날짜별 상세(우), FAB 앱의 캘린더 탭과 동일한 시각 언어
- 필드: `sdate`/`edate`/`stime`/`etime`/`tag`/`tagLabel`/`text`/`place`/`att`/`reg`/`isTodo`(v3.4.0 신규)
- **일정 등록 폼(v3.4.0)**: 메인 PJT(FAB)의 `openUsForm`/`saveUsSched`와 동일하게 개편
  - 카테고리: 반입/검수/교육/회의/설치/안전/휴무/연차/행정(9종, 구버전) → **교육/회의/반입/설치/휴무/안전/품질/기타(8종)**로 변경, 입력한 일정 내용을 바탕으로 카테고리 자동 추정(탭해서 변경 가능). 구 태그(검수/연차 등)로 저장된 과거 일정은 색상 매핑을 유지해 계속 정상 표시(하위호환)
  - **할 일** 체크박스 신규 — 체크 시 시간 입력 없이 체크리스트 항목으로만 등록(`isTodo:true`, `stime`/`etime` 공란 저장)
  - 시작/종료 시간 입력을 텍스트 → **시(0~24)/분(10분 단위) 드롭다운**으로 변경, 종료란에 "다중일 가능" 안내문구 추가
  - 등록자 필드에 **로그인 계정 이름+직급 자동 입력**(수정 가능)
- 상세보기 → 수정/삭제 가능 (v3.1 이전엔 삭제만 가능했음). 상세 화면의 기간 표시도 시간 미정(할 일)인 경우 "(시간 미정)"으로 표기
- 이번 개편으로 홈 통합캘린더(4.0)의 `HOME_SCHED_CATS`(9종, 구버전 그대로)와 태그 종류가 달라짐 — 스키마(필드 구조)는 계속 호환되므로 상호 조회는 정상 동작하지만, 카테고리 목록 자체는 더 이상 완전히 동일하지 않음(사용자 요청에 따라 FAB 개별 프로젝트 모듈 기준으로 통일)

### 품목현황 일괄 등록/수정
- "📋 일괄 등록/수정" 버튼(관리자 전용) → 모달

- **출역 화면 개편**: 저장 버튼 제거하고 체크·공수 입력 시 자동저장(`_attWriteChecks`/`_attWriteManday`), "✓ 전체 출역 체크/해제" 토글(`toggleAllAttCheck`), 개인별 공수 +/−0.5 조정 버튼(`adjustMandayLight`), 상단에 "출역 N명/전체 M명" 카운트 표시, "⚙️ 명단 관리" 패널로 화면 이동 없이 인원 추가·삭제(`toggleWorkerMgmtLight`).

**배경**: 대표님이 "P4 Ph2(FAB)랑 다른 PJT들이랑 동일하게 통일이 되겠냐"는 근본적 우려를 제기 — 실제로 FAB/SUP/경량PJT가 파일 3개로 완전히 분리돼 있어 기능 격차가 계속 재발하는 구조적 문제를 확인. 지금 당장은 파일 통합(큰 작업, 데이터 마이그레이션 리스크)까지는 진행하지 않고, 발견되는 격차를 하나씩 이식하는 방식으로 계속 진행하기로 함.

### 공사일보 탭 캘린더 뷰
- `initReportCal`/`renderReportCal`/`loadReportCalMonth`: 공사일보 탭 최상단에 월별 캘린더 신설. 작성된 날짜는 초록 점으로 표시(`.ddots`, 기존 일정관리 캘린더와 동일 마크업 재사용). 날짜 클릭(`pickReportDate`) 시 해당 날짜 작성/조회 화면으로 이동. 기존 이전/다음 화살표(`reportDayShift`)도 유지하며 캘린더 월 표시와 서로 동기화됨.

### 공사일보 → 업무일지 자동 연동
- `syncReportToDailyLog(d)`: 공사일보 저장(`saveReport`) 시, **현재 로그인한 포털 계정** 명의로 `edoc_daily`(전자결재 업무일지) 문서를 자동 생성/갱신. 금일 작업내용→오늘 진행 업무, 명일 예정→내일 예정 업무, 특이사항→특이사항으로 매핑. 결재선은 업무일지 표준과 동일(작성→김종화 결재→송지훈 수신), `status:'pending'`으로 저장돼 실제 결재 대기까지 자동 등록됨. 문서 ID를 `pjtreport_{pjtId}_{날짜}`로 고정해 같은 날짜 재저장 시 중복 생성 없이 덮어씀. **주의**: 공사일보 "작성자" 드롭다운에서 다른 사람 이름을 선택해도, 실제 업무일지는 지금 로그인해서 쓰고 있는 계정 쪽에 생성됨(그 계정이 포털에서 업무일지를 확인할 사람이므로).

### 공사일보 조회 UI 개선
- 조회 모달(`dr-list-modal`)이 화면 하단에 붙어서 뜨던 것을 중앙 정렬로 수정(`align-items:center`, 모서리 전체 라운드 처리).
- 조회 목록·사이드바 "최근 공사일보" 둘 다 품목 체크 내역 전체 텍스트를 미리보기로 보여줘서 가독성이 떨어지던 것을 날짜·작성자만 표시하도록 간소화. 상세 내용은 클릭해서 확인.

### 설정 탭 — 현장정보 전체 수정
- 기존엔 "공사 시작일"만 수정 가능했던 것을, 현장명·거래처·PJT 내용·품목·물량까지 전부 수정 가능하도록 확장(`saveBasic`이 `pjt_registry` 문서에 6개 필드 모두 patch).

### 근태관리 탭 — 날짜 클릭 이동
- 날짜 제목을 클릭하면 네이티브 날짜 선택기가 뜨도록 추가(`openAttDatePicker`/`pickAttDate`), 공정관리 탭과 동일한 방식.

### 사용 장비 하드코딩 제거 (버그 수정)
- **문제**: 공사일보 "사용 장비" 선택지가 P4 Ph2(FAB) 전용 지게차 번호(004나6452 등)로 HTML에 직접 하드코딩돼 있어서, **완전히 다른 경량PJT에서도 전부 똑같이 노출**되던 버그. 어떤 프로젝트든 같은 파일(`pjt_light/index.html`)을 공유하는 구조라 발생.
- **수정**: 드롭다운을 제거하고 자유 텍스트 입력(`+ 추가` 버튼, Enter로도 추가 가능)으로 변경. 프로젝트마다 실제 사용하는 장비를 직접 입력.
