## 작업 1 — 공사일보(daily-report) 저장 실패 근본 원인 수정 (v2.4.1)

**배경**: 대표가 공사일보 작성 화면(`daily-report/index.html`)에서 저장 시 "저장 실패: Missing or insufficient permissions." 알림이 뜬다며 스크린샷 첨부.

**원인**: `daily-report/index.html`에 Firebase Auth 초기화(`firebase-auth.js` import + `getAuth(app)`)가 전혀 없어 Firestore 요청이 항상 미인증 상태로 나갔고, 로그인을 요구하는 보안 규칙에 의해 저장이 거부됨. 다른 모든 모듈(`pjt`, `edoc`, `hr`, `gihoek`)은 각자 독립적으로 Auth를 초기화하고 있었는데 `daily-report`만 예외였음.

**권한 확인**: 공사일보 작성 권한 기준을 대표에게 확인 → PJT 권한(`perms.pjt`)과 동일하게 유지하기로 확정.

**수정**: `pjt/index.html`과 동일한 패턴으로 `getAuth(app)` + 접근 게이트(`onAuthStateChanged` → `portal_users` 권한 확인) 추가.

**검증 순서**: 로컬 `node --check` → portal-test 배포 → 대표 실 테스트(정상 저장 확인) → 프로덕션 배포.

**배포**: 코드(daily-report/index.html) · 버전 코멘트(index.html, daily-report 2.4.1) · 백업(`backup/v2.4.1/daily-report/`) · 기능 문서(`4_1_pjt_fab.md`) · 개발 로그(`7_28`) 완료.
