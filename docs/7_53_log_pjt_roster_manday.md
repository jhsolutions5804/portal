# 개발로그 — 근로자 연명부 v1.4.0 (④ 월간 공수 보기 이전)

> 작성: 춘식이(Claude) · 2026-09-30 · 배포: portal-test (본섭 대기)

## 요청 · 경과

- 연명부 재편 ④단계: 월간 공수(`pjt_manday`)의 "PJT별 합계 + 개인별 합계(공수표)"를 연명부로 이전.
- 월간 공수 코드 확인: 월 단위로 일자별 문서를 `getDoc`으로 반복 조회하고(FAB·SUP·경량PJT 각각 최대 31회), 명단의 ID로 근로자를 찾아 이름+생년월일 키로 합산. 공수표는 html2canvas로 PNG 저장.

## 설계 결정

- 연명부에 보기 전환(`명부` / `월간 공수`)을 두고 월간 공수 보기는 기존 화면의 구성(요약 카드 → 경고 → PJT별 → 개인별)을 유지.
- 팀별 합계(금액 포함)는 기획>정산으로 옮기는 ⑤ 단계 대상이라 이번에 이전하지 않음. 이 화면은 공수만 표시(금액 없음).
- 읽기 절감: 일자별 `getDoc` 반복을 `documentId()` 범위 조회 1회로 대체. 존재하지 않는 날짜 문서를 읽던 비용이 없어짐(Spark 일 5만 읽기 한도 보호). 일자 문서 ID가 `YYYY-MM-DD` 형식이라 사전순 범위가 정확함.
- 월간 공수의 `ambiguousIds`(FAB·SUP 동일 ID 경고)는 원본에서도 값이 채워지지 않는 죽은 코드라 이전하지 않음.
- 디버그 패널은 이전하지 않고 경고 문구(조회 실패·미등록 ID)로 대체.
