## 추가 세션 — PJT 토글 CSS "PC 미적용" 근본 원인 규명 및 수정 (같은 날, 후속 — 장시간 트러블슈팅)

### 경위
PJT 토글 디자인을 본섭에 반영했다고 보고했으나, 김짜장님 화면(Edge, 데스크탑 와이드 모니터)에서는 계속 옛날 박스형 버튼으로 보임. GitHub Pages 빌드 상태, DNS, 캐시, Windows 고대비 모드, forced-colors 미디어쿼리 등을 순서대로 배제하며 진단.

### 원인 규명 과정
1. GitHub Pages 빌드/DNS/캐시 전부 정상 확인(오탐 다수 발생, 김짜장님께 불필요한 캐시 삭제·재부팅 등 여러 차례 요청 — 결과적으로 헛다리)
2. 소스 텍스트 대조(Ctrl+F) 1차 시도에서 `F0F4F9` 검색 — 이 색상이 무관한 다른 요소(`.pjt-cal-nav`)에도 쓰여서 위양성 판정(잘못된 검증 방법)
3. 고유 문자열(`rgba(29,91,166,.25)`)로 재검증 → 소스엔 정상 포함 확인
4. 그런데도 화면 미반영 → DevTools Computed 패널 확인 → `background-color: buttonface`(브라우저 기본 버튼 색)가 승리 중 → Windows 고대비 모드 의심 → 확인 결과 "없음"으로 오답
5. DevTools Elements/Styles 패널 전체 캡처 요청 → **결정적 단서 발견**: `.pjt-cal-toggle`/`.pjt-svt-btn`/`.pjt-svt-btn.active` 스타일 전체가 `@media (max-width:899px)`(모바일 전용) 안에 갇혀 있었음. 즉 애초에 이 스타일 자체가 모바일에서만 적용되도록 작성되어 있었고, PC(900px 이상)에는 대응하는 전역/PC 규칙이 없어(PC 미디어쿼리엔 flex/padding/font-size 등 부분 조정만 있고 background/border 지정이 없음) 브라우저 기본 버튼 스타일로 떨어졌던 것이 근본 원인
6. `appearance:none` 누락도 별도로 발견해 함께 수정했으나(중간에 먼저 배포), 이것만으로는 해결 안 됐고 미디어쿼리 갇힘 문제가 진짜 원인이었음
7. portal-test도 동일한 구조였으나, test는 PC 미디어쿼리에 **완전한** 재정의(배경·테두리·글자색 전부 포함)가 별도로 존재해서 우연히 데스크탑에서 정상으로 보였던 것 — 테섭이 "정상으로 보인 이유"까지 규명됨

### 수정
- `.pjt-cal-toggle`, `.pjt-svt-btn`, `.pjt-svt-btn.active`를 모바일 전용 미디어쿼리에서 빼내 **전역 규칙**(PC/모바일 공통)으로 이동
