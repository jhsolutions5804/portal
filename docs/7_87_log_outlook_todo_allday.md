# 7.87. 개발로그 — Outlook 연동: 할 일도 반영 (종일 → 06:00~22:00로 개정)

> 2026-10-01 · 춘식이(Claude) · 대표님 지시: "포털에서 등록하는 모든 일정은 모든 직원의 아웃룩에 보여야 해", "할일은 아웃룩에 반영할 때 종일 이벤트로"

## 발단
- 모바일에서 10/2에 등록한 `(P4 Ph1) 4층 AHU(40101) 보수`가 Outlook(폰 앱·위젯)에 안 보임 → 일정 상세에 `할일`(isTodo) 표시. 기존 설계(7_65)가 "할 일은 반영하지 않음"이었다.
- 동기화 점검 중 서버 정상(저장 즉시 반영, 오류 없음)을 확인했고, 원인은 설계 규칙뿐이었다. (처음 점검에서 할 일을 걸러내고 세어 "10/1 이후 2건"으로 잘못 보고했다가 정정함)

## 변경 (outlook-sync/functions/lib/core.js 4곳, 함수 소스는 대표님 PC에만 있음)
1. `targetsFor`: `if (!s || s.isTodo) return [];` → `if (!s) return [];`
2. `toEvent`: `hasTime = validTime(s.stime)` → `!s.isTodo && validTime(s.stime)` (할 일은 항상 종일)
3. `toEvent` 범주: `[현장명, 구분]` → 할 일이면 `[현장명, 구분, '할일']`
4. 헤더 주석을 새 규칙으로 수정
- 제목 형식은 기존과 동일(`[현장명] [구분] 제목`, 완료 시 `✔ ` 접두). 알림 없음·한가함 표시 유지.
- 반영 범위: user_schedules·pjt_registry/*/schedules(+company_schedules). SUP(ph4_schedules)는 종료 프로젝트라 계속 제외.

## 검증
- 단위 테스트 15개 통과: 할 일 생성(종일·범주·✔)·시간이 남은 할 일도 종일·여러 날·완료 체크 변경 시 같은 이벤트 수정·변경 없음 건너뜀·삭제·일정↔할 일 전환, 일반 일정 5종·연명부 만료 일정은 이전 코드와 결과 동일(회귀 없음).
- 배포 후 실서버 확인: 오늘 이후 할 일 4건이 공유 캘린더에 종일 이벤트로 생성(범주 `P4 Ph2`·구분·`할일`, 알림 없음), 동기화 매핑 4/4 생성, 배포 이후 오류 0건, 중복 없음.

## 남은 것(→ 아래 "인사 일정 퇴사 라벨"로 해결)

## 개정 (2026-10-01 후속): 할 일을 06:00~22:00 시간 지정 일정으로
- 사유: 폰 Outlook 위젯(삼성 홈 화면)은 종일 일정을 `하루 종일:` 한 줄로 작게 합쳐 보여 눈에 띄지 않음. 대표님 요청으로 할 일을 06:00~22:00 일정으로 올리기로 함(삼성 캘린더 연동 검토 결과가 "전 직원 공통 해법으로는 약함"일 때의 대안으로 사전 결정).
- 삼성 캘린더 연동 검토: 포털→삼성 직접 연동 경로는 없음. Outlook for Android의 `Sync calendars`로 Outlook 캘린더를 삼성 캘린더에 내보낼 수는 있으나 공유·위임 캘린더(PJT 일정)가 포함되는지는 미확인이고 직원마다 폰 설정이 필요 → 전사 해법으로 채택하지 않음.
- 변경(core.js): `TODO_START='06:00'`, `TODO_END='22:00'` 상수 추가. 할 일은 포털 시간 값과 무관하게 `[시작일 06:00 ~ 종료일 22:00]`, 시간 지정 일정(isAllDay=false). 제목·`할일` 범주·✔·한가함·알림 없음은 동일. 값 변경은 두 상수만 수정.
- 검증: 단위 테스트 15개 통과(할 일 동작 8건 + 일반 일정이 변경 전·직전 배포본과 동일한 회귀 6건 + 연명부 만료 1건). 기존 종일 이벤트는 같은 이벤트를 수정(중복 생성 없음).
- 배포: 대표님 PC, 같은 4개 함수 Successful update. 실서버 확인: 오늘 이후 할 일 전부 06:00~22:00로 전환(10/1·10/2·10/6·10/8 + 배포 후 새로 등록된 10/7 `PCM 개정본 제출`), 중복 없음, 오류 0건. 새로 등록한 할 일은 저장 즉시 같은 방식으로 자동 반영됨을 확인.

## 인사 일정 `퇴사` 라벨 (2026-10-01 후속, hr-sync.js)
- 증상: 승인된 퇴직원서의 퇴사 일정이 Outlook 인사 일정에 `[기타] 형일우 퇴사`(범주 기타)로 표시(`TYPE_LABEL`에 `resign` 없음).
- 변경: `TYPE_LABEL`에 `resign:'퇴사'` 추가 + 퇴사 구분에 한해 자동 등록 제목의 끝 `퇴사`를 떼어 `[퇴사] 형일우`로 표시(`[퇴사] 형일우 퇴사` 중복 방지). 다른 구분은 변경 없음.
- 검증: 단위 테스트 13개 통과(퇴사 구분 신규 동작·다른 구분 7종이 이전과 동일·기존 이벤트는 신규 생성 없이 수정). 배포(`functions:outlook-sync:syncHrCalendar` 1개, 대표님 PC) 후 형일우 건에 갱신 표식을 넣어 반영 → Outlook 인사 일정에서 `[퇴사] 형일우`(범주 퇴사, 9/16 종일, 한가함)로 변경 확인, 오류 0건, 중복 없음.
- 롤백: 이전 hr-sync.js로 되돌려 같은 함수만 재배포.
