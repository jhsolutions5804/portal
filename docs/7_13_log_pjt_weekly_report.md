# 7.13. 개발 로그 — PJT 주간공정회의 자료 자동생성 + 도면 좌표 매핑 (v5.3.0)

## 배경

기존 `공정표 PPT`(일별)와 별개로, 매주 정기적으로 발표하는 주간공정회의 자료(전주 대비 금주 누계·공정률 비교표 + 구역별 도면)를 수기로 만들던 걸 자동화. 원본 양식(파일1)·기존 일별 PPT 산출물(파일2)을 분석해 설계.

## 레이아웃 설계 노트

- 최초 설계 시 파일1 원본 PPTX의 `<p:pic>` XML(`rot="5400000"`, off/ext EMU값)을 직접 파싱해 도면이 **90도 회전된 가로 스트립**(약 9.7"×2.3")으로 배치된다는 걸 확인 → 처음 설계했던 세로형 5.0"×3.55" 박스를 전면 폐기하고 `wrFitContain()`(object-fit:contain 방식) 기반 가변 배치로 재설계
- 사용자 제공 도면 5장(X-OB·복합4동·복합3동·W-OB·2F 제조부속실) + 파일1에서 추출한 3F FIZ 도면(90도 회전 정규화) = 총 6장 확보

## 검증 방법론

- `node --check`: 멀티라인 `import {...}\n  from '...'` 구문은 일부 정규식 기반 스트립 방식이 놓칠 수 있음을 이번에 발견 → 진짜 `.mjs` 확장자로 저장해 검증하는 방식이 더 정확
- **jsdom 실제 실행 테스트**: 문법 검사만으로는 "함수가 실행은 되지만 특정 시점에 필요한 전역함수가 없어서 무시되는" 류의 버그(예: 복구 패치로 인한 함수 분절)를 못 잡음 → `vm.runInContext`로 실제 브라우저처럼 스크립트를 실행하고 `openLayoutMapModal()` 등 핵심 함수를 직접 호출해 DOM 결과(장비 리스트 개수, 이미지 src 등)까지 확인하는 방식으로 전환. 이후 이 방식을 프로덕션 배포 직전 최종 검증에도 사용
- Firebase/PptxGenJS는 mock 처리해 네트워크 없이 로직만 검증

## 데이터 이관

Claude 환경은 `googleapis.com` 접근이 막혀있어 Firestore 직접 조작 불가 → `scripts/migrate_zone_layouts.py`(firebase-admin 기반) 작성해 사용자가 로컬에서 실행하는 방식으로 `zone_layouts` 컬렉션을 portal-test → 프로덕션으로 이관.
