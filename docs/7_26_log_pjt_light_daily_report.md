# 7.26 — 경량 PJT: 공사일보 고도화 + 품목현황 일괄 등록/수정 (v3.3.0)

**날짜**: 2026-08-20
**대상**: `pjt_light/index.html` (경량 PJT 워크스페이스, 모든 경량 PJT가 공유하는 단일 파일)

## 배경
경량 PJT의 공사일보가 "작성자(자유입력)/작업내용/특이사항 + 최근 목록" 정도의 미니 시스템이었던 반면, 메인 PJT(FAB)는 별도 앱(`daily-report/index.html`)에서 작성자 마스터명부/공정 자동반영/근태 자동반영/장비/PDF/조회·수정·삭제까지 지원하는 완성형 시스템이었음. 사용자 요청으로 경량 PJT도 동일 수준으로 고도화.

## 설계 결정
- FAB처럼 별도 파일(`daily-report/light.html` 등)로 분리하지 않고, **`pjt_light/index.html`의 공사일보 탭 안에서 직접 확장**하기로 함. 경량 PJT는 파일 하나를 모든 프로젝트가 공유하는 구조이므로(`?pjtId=`), FAB/SUP처럼 프로젝트별 파일을 늘리는 방식(ph4.html 패턴)은 이 구조와 맞지 않음.
- 품목현황 체크에 날짜별 로그(`item_checks/{날짜}`)가 없어서 "오늘 무엇을 체크했는지"를 재구성할 방법이 없었음 → `toggleItemStage`에 날짜 로그 기록을 추가해서 해결(기존 `items.stages`는 그대로 유지, 신규 서브컬렉션만 추가하는 방식으로 하위호환 보장).

## 구현
1. **공사일보**
   - 작성자: `portal_users` 컬렉션에서 이름+직급 드롭다운 생성, 로그인 계정 자동 선택
   - 금일 작업내용: `item_checks/{날짜}` + `items` 컬렉션으로 자동 문장 생성(재불러오기 버튼 포함), 저장된 일보가 있으면 저장값 우선 표시
   - 명일 예정 작업 필드 신규
   - 투입 인원: `attendance/{날짜}.checks.length` 자동 반영
   - 공수: `manday/{날짜}.md` 합계를 인원수로 나눈 1인당 평균으로 자동 반영 → 화면엔 `인원 × 공수 = 합계 투입공수`로 실시간 계산해서 보여줌(사용자 피드백 반영: 처음엔 합계만 자동표시했으나, 인원×공수 곱셈 형태로 명시적으로 보여달라는 요청에 따라 개편)
   - 사용 장비: 칩 선택 UI (FAB과 동일한 지게차 자산 목록 재사용)
   - 미리보기/PDF: 인쇄용 문서 HTML 생성 후 `window.print()`
   - 조회: "전체보기"→목록 모달→클릭 시 상세보기 모달(수정/삭제/PDF)
2. **품목현황 일괄 등록/수정**
   - 붙여넣기 일괄 추가(순수 추가, `writeBatch`)
   - 기존 품목 이름수정/삭제를 목록에서 한번에 저장 — **문서 ID로 매칭**하여 이름 변경 시에도 기존 `stages`(진행 체크 데이터) 보존

## 검증
- `node --check`로 module script 문법 검증
- HTML `onclick`/`onchange` 참조 함수 전수 정의 여부 정적 검증(정규식 매칭)
- jsdom + 인메모리 모의 Firestore(`get/set/update/delete/writeBatch` 포함 자체 구현) 로 실제 실행 검증:
  - 자동반영(품목체크→작업내용, 근태→인원, 공수합계→1인당평균) 정상
  - 저장/조회/수정/삭제 순환 정상, `mandayTotal` 재계산 정상
  - 장비 칩 추가/삭제 정상
  - 품목 일괄추가(빈 줄 무시) 정상, 일괄수정 시 이름변경해도 stages 보존 정상, 삭제 마킹 정상
- 테스트 하네스 참고: Node 순수 ESM 환경에선 `window.foo=...`로 등록한 함수를 모듈 내부에서 bare(`foo()`)로 호출하는 기존 코드 관행이 실제 브라우저와 달리 즉시 실행 안 되므로(`window`≠`global`), 테스트 시에만 `window`의 함수를 `global`에 브릿지해서 검증함 — 실제 배포 코드에는 영향 없음(브라우저에서는 window가 곧 global이라 정상 동작)
