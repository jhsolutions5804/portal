## 목적 · 범위

공수 체크와 건강검진 이력 관리를 쉽게 하기 위한 근로자 연명부. 월간 공수(`pjt_manday`)의 "근로자 마스터 관리"를 이전(② 단계)하고 인적사항·검진·자격·교육·포털 계정·첨부 파일을 확장 관리한다.
- 진행 순서: ① 골격+개인정보 폼 → ② 마스터관리 이전(v1.0.0에서 ①+②를 함께 구현) → ③ 마이그레이션 도구 → ④ PJT별 합계·공수표 → ⑤ 기획>정산 팀별 노무비 → ⑥ 월간 공수 메뉴 정리 여부.
- ①의 로컬 빌드는 저장소에 올라간 적이 없어 새로 구현함.
- 제외(결정): 정기/특별안전교육 실시일·교육시간·누적시간(추후 PJT 관리에서 연동).

## 데이터 구조

| 컬렉션 | 문서 ID | 내용 | 접근 |
|--------|---------|------|------|
| `master_workers` (기존) | `이름_생년월일`(특수문자 제거) | `name, birth, leaderId, dailyRate, resigned, resignedDate` + 신규 `gender, hireDate` | 승인된 직원(기존과 동일) — FAB/경량PJT/SUP이 그대로 읽음 |
| `master_worker_private` (신규) | 동일 ID | `jumin, phone, bank, account, health[], certs[], inhouseEdu{e1..e4}, inhouseEduExp{e1..e4}, ssId, ssPw, note, files{photo,idcard,cert}, hasPhoto, updatedAt` | **관리자만** |
| `master_worker_photos` (신규) | 사진 `ID` · 신분증 `ID__idcard` · 건설기초이수증 `ID__cert` | `dataUrl`(JPEG base64), `mime, fileName, size, slot, updatedAt` | **관리자만** |

- 민감정보(주민번호·연락처·계좌·검진·포털 계정)와 첨부 파일은 모든 PJT 모듈이 읽는 `master_workers`에 넣지 않고 관리자 전용 컬렉션에 분리.
- 일당(`dailyRate`)은 월간 공수(팀 단가 집계)가 `master_workers`에서 읽으므로 그 컬렉션에 유지 — 화면에서만 관리자 구역에 표시. 연명부를 관리자 외에도 열게 되면 별도 컬렉션 이전(+월간 공수·정산 수정)이 필요.
- 퇴사처리는 기존과 같이 `master_workers.resigned/resignedDate`만 바꿈 → 각 PJT 모듈의 퇴사자 처리에 자동 반영.
- `certs[]` 항목: `{co:'samsung'|'skhynix', name, site(취득 현장명), acquired, expiry}`. `co`가 없던 기존 자격은 삼성전자로 간주하고 저장 시 부여.
- `files.{photo|idcard|cert}` = `{name,size,w,h}` 또는 `null`. 예전 단일 사진 필드(`photoName` 등)는 읽을 때 `files.photo`로 승격하고 저장 시 비움.

## 화면 · 기능

- 요약: 재직/퇴사 인원, 일반검진 기록 없음(재직), 사내화 교육(삼성전자) 미완료·만료(재직).
- 목록: 재직/퇴사/전체 필터, 이름·연락처·**자격명·취득 현장명** 검색. 열: 이름, 성별, 주민번호(뒷자리 마스킹), 전화번호, 입사일, 소속, 일반/배치전검진 최근일, 사내화 교육(n/4 + 만료/임박), **자격·인증(원청별 건수 칩, 만료 ⚠)**, 첨부(사진·신분증·이수증 칩).
- 등록/수정 폼 순서: **인적사항**(이름, 주민번호, 생년월일, 성별, 전화번호, 입사일, 퇴사일(읽기), 소속(팀장)) → 건강검진 이력(일반검진·배치전검진, 여러 건) → **원청별 탭** → 사진 파일 3칸 → 비고 → **🔒 관리자 전용 조회 · 급여/계좌**(은행, 계좌번호, 일당).
- 원청별 탭(`삼성전자` / `SK하이닉스`, 탭 라벨에 자격 건수):
  - 삼성전자: 자격·인증 / 사내화 교육 이수 여부(체크 + 만료일, 만료됨·D-N·유효 표시) / 상생협력포탈 ID·PW(마스킹·👁 표시·복사)
  - SK하이닉스: 자격·인증
  - 상생협력포탈 계정을 삼성전자 탭에 둔 것은 사내화 교육과 같이 삼성전자 전용으로 본 가정 — SK에도 필요하면 SK 탭에 추가.
- 자격·인증: 자격/인증명, **취득 현장명**, 취득일, 만료일. 만료일 경과 시 “만료됨”, 30일 이내 “D-N”. 자격명 없이 다른 값만 있는 행은 저장 차단.
- 주민번호 입력 시 생년월일·성별 자동 입력. 외국인등록번호는 검증번호 불일치 시 경고 후 저장 허용.
- 팀장 가드: 팀원이 지정된 팀장은 삭제·퇴사처리·소속 변경 불가(월간 공수와 동일).
- 저장은 `writeBatch`로 master·private(·photos)를 함께 커밋.

### 사내화 교육 여부 목록 (`inhouseEdu` / 만료일 `inhouseEduExp`) — 현재 삼성전자 탭에만 적용
`e1` 안전담당자/화재감시자 기본 인증과정 · `e2` 중량물/양중작업(통합) 안전인증과정 · `e3` 화학물질취급작업 안전인증과정 · `e4` 화학물질안전원 온라인 안전교육. 체크를 풀면 만료일이 비워짐. 목록 요약의 "미완료·만료" = 4종 미이수 또는 만료 1건 이상.

### 첨부 파일 3칸 (파일 형태 보관)
- 칸: **사진 · 신분증 · 건설기초이수증**. 각 칸 [보기](모달)·[다운로드](`이름_사진.jpg` / `이름_신분증.jpg` / `이름_건설기초이수증.jpg`)·[교체]·[삭제]. 화면에 바로 표시하지 않고 파일명·해상도·용량만 표시.
- 저장 전 브라우저에서 JPEG로 변환·축소: 긴 변 최대 **2000px**, dataURL **950,000자(원본 약 710KB)** 이하가 되도록 화질(0.86→0.55)·크기를 단계적으로 낮춤. 이미지 파일만 가능(PDF 불가).
- 보안규칙 상한 1,000,000자 미만·이미지 MIME 정규식 검사, Firestore 문서 한도(1MiB) 여유 확보.
- 용량: 1인 최대 3장 ≈ 2.1MB → 300명 최대 약 640MB(Spark 무료 1GiB의 약 63%, 실제로는 대부분 더 작음). 누적 추이를 보며 관리. Cloud Storage는 Blaze 필요라 사용하지 않음.

## 접근 제어

- 모듈: `portal_users/{uid}.admin===true && status==='approved'` 확인(월간 공수와 동일), 아니면 접근 차단 화면. 포털 셸도 관리자에게만 메뉴 노출(`openModule` 가드 포함). 관리자 전용 구역은 `isAdmin`일 때만 그려지고, 비관리자라면 은행·계좌·일당은 저장 대상에서도 제외되도록 구현.
- **보안규칙(테섭 배포 완료)**: `isAdminOnlyCollection()`을 신설하고 catch-all(`/{document=**}`)에서 제외. Firestore 규칙은 일치하는 match 중 하나라도 허용하면 허용(OR)이라, catch-all에서 제외하지 않으면 개별 match만으로는 제한되지 않음(배포 전 규칙에서 일반 승인 사용자가 읽을 수 있음을 에뮬레이터로 확인). 첨부 3칸의 문서 ID는 같은 컬렉션이라 규칙 변경 불필요.
- 규칙 사본: portal-test `backup/firestore_rules_20260930/firestore.rules.before|after`.

## ⚠️ 보안 참고

- 상생협력포탈 비밀번호는 관리자 전용 영역에 **평문 저장**(암호화 아님). 개인 비밀번호가 아닌 업무용·초기 비밀번호만 보관. 프로젝트 내 관리자 서비스 계정 키는 규칙을 우회하므로 키 관리 주의. 필요 시 입력 암호(WebCrypto AES-GCM) 방식으로 변경 가능(암호 분실 시 복구 불가).
- 주민번호·계좌번호도 평문 저장(관리자 전용 컬렉션). 목록은 마스킹.
