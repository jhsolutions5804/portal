# 7.72. 개발로그 — 보안 2단계: 직원 비밀번호(_pw) 저장 위치 이동

> 2026-09-30 · 춘식이(Claude) · 배포: **테섭 적용 완료 / 본섭 미적용**

## 배경
1단계(`7_71`)로 스스로 관리자 승격·타 계정 수정은 막았지만, 계정 문서의 `_pw`(비밀번호를 base64로만 감싼 값)를 승인된 직원이 읽을 수 있어 관리자 계정 비밀번호를 알아내는 경로가 남아 있었음.

## 설계
- `_pw`의 용도: 관리자가 직원 비밀번호를 바꿀 때(`changeEmpPw`) 저장된 현재 비밀번호로 그 직원 계정에 보조 앱으로 로그인해 변경. 기능은 유지하고 저장 위치만 이동.
- 새 문서 `portal_secrets/{uid}` `{pw, updatedAt}` — 규칙: 관리자 또는 본인(승인 상태)만 읽기·쓰기, 포괄 규칙에서 제외(`isAdminOnlyCollection`).
- 코드 4지점(`index.html`): 계정 생성(계정 문서에서 `_pw` 제거 + 별도 문서 저장), 관리자 비밀번호 변경(읽기: 새 위치 우선·옛 위치 폴백 / 쓰기: 새 위치 + 옛 `_pw` 제거), 내 정보 저장(새 위치 + 옛 `_pw` 제거), import에 `deleteField`.
- 전환 순서: 규칙(전환용) → 코드 → 데이터 이전 → 규칙(최종). 최종 규칙은 직원 본인의 계정 문서 수정 예외를 `phone`·`phoneVerified`·`phoneVerifiedAt` 3개로 축소.

## 검증
- 규칙 에뮬레이터 15항목 + 계정 문서 회귀 전환용(본섭 29·테섭 32)·최종(본섭 29·테섭 32).
- 코드 18항목(실제 함수 추출 실행): 계정 생성(계정 문서에 `_pw` 없음·새 문서에 한글 비밀번호 포함 저장), 관리자 변경(새 위치/옛 위치 폴백·자동 이전/양쪽 시 새 위치 우선/없으면 현재 비밀번호 입력 요청/직접 입력/불일치 거부/6자 미만 거부), 내 정보(전화번호·비밀번호·빈 비밀번호·6자 미만).
- 이전 스크립트: 에뮬레이터 dry-run·적용·덮어쓰기 방지·멱등.

## 본섭 적용 시 (대기)
같은 순서: 본섭 전환용 규칙(`firestore.rules.prod_transition`) → 본섭 `index.html` 패치(본섭 최신본 위에 4지점만) → 이전 스크립트(본섭 서비스 계정) → 본섭 최종 규칙(`prod_final`). 열려 있는 브라우저 탭은 새로고침 필요(구 코드가 계정 문서 `_pw`를 쓰면 최종 규칙에서 거부됨).

## 남은 것
- 비밀번호는 여전히 base64(가역)로 관리자·서비스 계정이 읽을 수 있음. 근본 해결은 저장하지 않는 방식(관리자 화면에서 재설정 메일 발송 `sendPasswordResetEmail` — 코드에 import는 이미 존재)이며 별도 검토.
