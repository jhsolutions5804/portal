# 7.77. 개발로그 — 일정 통합(“일정”) + GUEST 사번 제한

> 2026-09-30 · 춘식이(Claude) · 배포: **테섭** (본섭 미반영)

## 요청·결정 (대표님)
“일정은 좀 구분하고 싶은데. GUEST 사번은 회사 일정을 못 보게, PJT 일정만.” → 결정: ① **B안(화면 + 보안규칙)** ② **GUEST = 사번 기준** ③ “PJT·회사 이런 거 다 빼고 그냥 일정으로만 보자, 모바일에서도 캘린더로” ④ **GUEST 사번은 일정 등록 불가**

## 확인한 사실
- GUEST 사번 = `guest001`, `guest002`(본섭·테섭 각 이경택·서민우). 사번 필드는 전 계정 문자열.
- 회사 일정 = `company_schedules`(연차 신청서 게시 시 자동 등록, 직원 이름·연차 일수 포함). 본섭 14건. 기존엔 보안규칙 없이 승인 직원 누구나 읽기·쓰기.
- 일정 쓰기 경로: PC 포털 홈 캘린더, pjt·pjt_ph4(저수준 `_usSave/_usSetDone/_usDelete/_usUpdate` 4개), pjt_light, 모바일 pjt, 모바일 schedule, 전자결재 연차 게시(공통 일정 쓰기).
- 모바일에는 공통 일정 화면이 없었음(홈 배너·일정 화면은 프로젝트 일정만). 직전 작업에서 PJT 관리에 넣은 “회사 일정” 메뉴가 실제로는 오늘 일정(프로젝트 일정) 화면으로 연결돼 이름이 사실과 달랐음 → 이번에 통합 일정 화면으로 만들고 이름을 “일정”으로 정정.

## 결정 사항(문서화): GUEST는 완료 체크도 불가
“일정 등록 못 하게”를 읽기 전용으로 해석(등록·수정·삭제·완료 체크 모두 차단). 현장 완료 체크가 필요하면 규칙에서 `done`·`doneUpdatedAt` 갱신만 허용하도록 완화 가능(대표님 결정 시).

## 시험 중 발견한 결함
1. **보안규칙**: 경로 인덱스 오류로 경량 PJT 문서 읽기가 전원에게 막힘 → 경로 패턴 방식으로 수정(위 README).
2. 시험 도구 문제 3건(추출 함수의 window 객체, 데이터 타입 표기, 앵커 문자열)은 코드 결함이 아니어서 시험을 정정.
