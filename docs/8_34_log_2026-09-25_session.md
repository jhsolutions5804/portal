## 요청 (순서대로)

1. 반차는 4시간만 반영, 8시간 아님.
2. 퇴사자는 퇴사한 월까지만 근로시간 탭 명단에 나오게.
3. 연봉계약서·근로계약서도 근로자 명부처럼 퇴사자 항목 분리.
4. 최근 7일 공수 합계가 아니라 전체 공수표 조회.
5. 경량PJT 공정관리에서 특정 날짜(예: 9/22)에 작업한 물량을 체크할 수 없는 문제.
6. 프로젝트 수정에서 정보 수정하면 PJT 관리에도 바로 반영.
7. 날짜 가운데 클릭하면 원하는 날짜로 이동(캘린더).
8. 전혀 별개의 PJT에서 P4 Ph2 사용 장비가 섞여 나오는 문제.
9. (진행 중 질문) "P4 Ph2랑 다른 PJT들이랑 동일하게 통일이 되겠냐" — 구조적 우려 제기.
10. 공사일보 조회 팝업 위치·내용 개선, 설정 화면 확장, PJT 코드 동기화 등 후속 스크린샷 기반 세부 요청 8건.
11. 기획→PJT관리 동기화 시 "이름"이 아니라 "PJT 코드"를 기준으로.
12. 테섭에만 있고 본섭에 없는 과제 정리 후 전부 본섭 반영.

## 진단 — 구조적 문제 확인 (9번 관련)

FAB(`pjt/index.html`)·SUP(`pjt_ph4/index.html`)·경량PJT(`pjt_light/index.html`)가 완전히 분리된 파일이라, 기능을 하나씩 이식해도 다음에 또 격차가 생기는 근본 구조임을 확인해 대표님께 그대로 설명. 당장은 파일 통합(데이터 마이그레이션 필요, 리스크 큼)까지 가지 않고 발견되는 격차를 계속 이식하는 방식으로 진행하기로 합의.

## 구현

### 인사 — 반차 4h / 퇴사자 필터 / 계약서 탭 (hr v2.13.0, edoc v4.5.1)
- `hrComputeLeaveHoursForMonth`(인사)·edoc 동일 함수: 반차 판정을 `leaveType` 문자열뿐 아니라 저장된 `days`/`leaveDays`가 0.5인 경우도 인정하도록 강건화. 관리자 휴가부여 모달에서 반차 선택 시 일수 자동 0.5.
- 근로시간 탭 직원 목록: `otFilterWorkersForMonth`로 퇴사자는 퇴사월까지만 표시.
- 연봉계약서·근로계약서 목록: 🟢재직자/🔴퇴사자 필터 탭 신설.
- 상세: `2_8_hr_worktime.md`, `2_2_hr_labor_annual_r3.md`, `2_3_hr_annual_r2.md`.

### 경량PJT — 표준화 후속 (pjt_light v3.5.0→v3.6.0)
- 4·5·8번은 조사 결과 **이미 다른 세션에서 구현되어 있던 기능**(전체 공수표, 공정관리 날짜별 소급수정, 출역 화면 개편)으로 확인 — 문서화만 누락돼 있어 이번에 정리해 기록.
- 공사일보 탭에 캘린더 뷰 신설(작성일 점 표시, 클릭 이동).
- 공사일보 저장 시 로그인 계정 명의로 전자결재 업무일지 자동 생성/갱신 — 별도 작성 불필요.
- 공사일보 조회 모달 화면 중앙정렬(기존엔 하단에 붙어서 뜸) + 목록에서 내용 미리보기 제거(날짜만, 상세는 클릭).
- 설정 탭에서 현장명·거래처·PJT내용·품목·물량 전체 수정 가능(기존엔 공사시작일만).
- 근태관리 탭도 날짜 클릭 시 날짜선택기로 이동(공정관리는 이미 있었음).
- **버그 수정**: 공사일보 "사용 장비"가 P4 Ph2 전용 지게차 번호로 하드코딩돼 있어 전혀 다른 프로젝트에도 그대로 노출되던 문제 — 자유 텍스트 입력으로 교체.
- 상세: `4_3_pjt_light.md`.

### 기획 — 연동 PJT 동기화 (gihoek v5.7.0→v5.7.3)
- 처음엔 "설명"·발주처를 연동 항목에 동기화하도록 구현했다가, 대표님이 "이름이 아니라 PJT 코드를 기준으로"라고 정정 → 최종적으로 **PJT 코드**를 연동된 `pjt_registry`의 `name`(=PJT관리 사이드바 표시명)에, 발주처는 `client`에 동기화하도록 변경. 신규 자동생성 시에도 동일 우선순위 적용.
- 상세: `1_1_gihoek_project.md`.
