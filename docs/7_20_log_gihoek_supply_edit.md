# 7.20. 개발로그 — 견적 작성 시 합계금액 대신 공급가액 직접수정으로 변경

> 작성: 춘식이(Claude) · 2026-08-18

---

## 요청

견적 작성 화면 하단 합계란에서 지금까지는 "합계금액"(부가세 포함)을 직접 수정하는 방식이었는데, "공급가액"을 직접 수정하는 방식이 더 낫겠다는 요청.

## 기존 방식의 문제

- `onTotalEdit(v)`: 사용자가 입력한 합계금액(X)을 `공급가 = X / 1.1`로 역산하여 마지막 품목 금액에 반영
- 나눗셈 특성상 부가세가 딱 떨어지지 않는 금액(예: 합계 272,800,001원 등)을 입력하면 반올림 오차 발생 가능
- 실무에서는 보통 공급가액(계약/견적 기준 금액)을 먼저 정하고 부가세·합계를 계산하는 흐름이 자연스러움

## 수정

- 합계란 UI: "공급가액" 입력창(직접 수정 가능) + "부가세(10%)"·"합계금액"은 읽기전용 자동계산으로 순서 변경
- `onTotalEdit(v)` → `onSupplyEdit(v)`로 교체: 입력값을 그대로 목표 공급가액(X)으로 사용, 마지막 품목이 차액 흡수 (÷1.1 역산 단계 제거 → 반올림 오차 없음)
- `recalcTotals()`: 공급가액 input은 값(`value`) 갱신(단, 포커스 중일 땐 건드리지 않음 — 커서 튐 방지), 부가세·합계는 텍스트로 표시

## 검증

- Node.js로 계산 로직 시뮬레이션: 공급가액 248,000,000원 입력 → 부가세 24,800,000원, 합계 272,800,000원 정확히 산출 확인
- `node --check` 문법 검증 통과 (gihoek/index.html 유일한 `<script type="module">` 블록)
