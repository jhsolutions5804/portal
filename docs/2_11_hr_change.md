## 목적 · 범위

인사 개편의 "변동" 단계. 승진·부서 이동·연봉 조정을 한 화면에서 처리하고 이력을 모아 본다.
- 포함: 직급 변경, 부서 변경, 연봉 조정(근로계약서 작성으로 연결), 변동 현황 조회.
- 제외(결정 2026-09-30): 현장 배치 변경, 퇴사 후속 서류(재직/경력증명서, 4대보험 상실 등), 입사 서류 체크리스트. 4대보험 등은 원청 PJT 포털에서 처리.

## 메뉴 위치

- 인사 홈 업무 흐름: ① 채용 → ② 입사처리 → ③ 재직중 관리 → **④ 변동(신설)** → ⑤ 퇴사. 단계 번호 1~15로 재정렬(변동=12, 퇴사=13~15).
- 인사 상단 탭바 `🔄 인사 변동`(연차 현황 다음), 포털 사이드바 `HR_SUBTABS`에 `change` 추가(루트 `index.html`, 번호 12~15 재정렬).

## 화면 구성

1. **변동 처리** — 근로자 선택(재직자만) → 현재 소속·직급·호봉·현재 계약연봉 표시 → 변경 직급/부서, 시행일, 사유 입력.
2. **연봉 조정 버튼** — `goTab('labor',{noRender:true})` → `renderLaborRegister()` → 근로자 선택 + 시작일(=시행일)·종료일(시작일+1년−1일) 프리필. 서명 문서는 자동 생성하지 않음(저장 서류 불변 원칙).
3. **변동 현황** — 최근순 목록, 유형 필터(전체/직급/부서/연봉), "선택한 근로자만" 체크. 최대 200건.

## 저장 동작 (`chgSave`)

| 항목 | 내용 |
|------|------|
| 검증 | 변경 없음 차단, 시행일 필수, **시행일은 오늘 이전만**(저장 즉시 명부에 반영되므로) |
| 명부 반영 | `workers/{id}` merge: `rank`(변경 시), `dept`(변경 시). 직급 변경 시 `step=1`, `stepYear=올해`로 호봉 초기화 |
| 이력 | `workers/{id}/history` addDoc: `type`(rank/dept/both), `fromRank/toRank/fromDept/toDept`, `reason`, **`effectiveDate`**(신규 필드), `changedAt` |
| 포털 동기화 | `portalUid`가 있으면 `postMessage({source:'jh-hr', action:'syncWorkerToPortal', payload:{puUid, fields:{name,rank,dept}}})` |

- 명부 수정 화면(`rosterDetailSave`)의 직급·부서 변경 이력 저장은 기존 그대로 유지. 두 경로 모두 같은 `history` 컬렉션을 쓰므로 명부의 "변경 이력" 모달과 이 화면의 현황에 동일하게 나온다. (`effectiveDate`가 없는 기존 이력은 `changedAt` 날짜로 표시)

## 연봉 변동 산출 방식

별도 이중 기록을 만들지 않고 저장된 `annual_contracts/{id}/contracts`의 `salary` 변화에서 산출한다.
- `startDate` 오름차순(같으면 `savedAt`)으로 정렬, **같은 시작일의 중복 계약은 마지막 저장본만** 사용.
- 첫 계약은 변동이 아님. 이후 계약의 `salary`가 직전과 다를 때만 "연봉 A → B" 이벤트, 날짜는 계약 시작일.
- "현재 계약연봉"은 가장 늦은 시작일 계약의 `salary`.
- 근거: 이 시스템의 연봉은 근로계약서의 시급/월급/연봉 입력에서 산정되어 연봉계약서로 이어지므로, 연봉 금액을 변동 화면에서 직접 입력받지 않는다.

## 알려진 한계

- 연봉 변동은 연봉계약서가 저장된 뒤에야 현황에 나타난다(조정 버튼 → 근로계약서 → 연봉계약서 흐름을 끝내야 반영).
- 시행일이 미래인 예약 변경은 지원하지 않음.
- 직급 선택 목록 = `RANKS2` + 현재 근로자들이 쓰는 직급, 부서 = `DEPTS2` + 현재 사용 중인 부서.

## 수정 이력 (2026-10-01)

### hr 2.24.1 — 인사 변동 화면이 '불러오는 중'에서 멈추던 오류
- 증상: 인사 변동 탭이 열리지 않고 콘솔에 `ReferenceError: RANKS2 is not defined` (`_chgRender`).
- 원인: 직급·부서 기본 목록 `RANKS2`/`DEPTS2`가 `rosterDetail()` 함수 **안에서만** 정의돼 있는데, 인사 변동 화면(`_chgRender`)이 모듈 최상위에서 같은 이름을 썼다. 2.14.0(신설)부터 있던 문제로, 한 번도 정상 렌더링된 적이 없었다.
- 수정: 인사 변동 전용 상수 `_CHG_RANKS`(과장·대리·사원)·`_CHG_DEPTS`(6개 부서)를 모듈 최상위에 두고 `_chgRender`가 이를 쓰도록 변경. 값은 기존과 같고, 실제 근로자가 가진 직급·부서가 합쳐져 선택지에 나온다.
- 같은 종류 오류 점검: 인사 모듈 전체를 정적 분석(ESLint `no-undef`)해 추가 미정의 변수 없음 확인.

### hr 2.24.2 — 호봉 산정 규칙 정정
- 호봉(`calcWorkerStepNow`)은 근로자 명부에 직접 저장한 값(`step`·`stepYear`)이 있으면 그 해부터 매년 +1, 없으면 입사일로 추정한다.
- **추정 규칙(정정)**: 입사한 해는 분기와 관계없이 **1호봉**. 다음 해 1/1부터 1~3분기 입사자는 2호봉, 4분기 입사자는 1호봉으로 시작해 이후 매년 1/1에 +1.
  - 정정 전: 1~3분기 입사자가 입사한 해에도 2호봉으로 표시됨(예: 2026-05 입사 → 2026년 2호봉).
  - 예: 2026-05 입사 → 2026년 1호봉 / 2027년 2호봉 / 2028년 3호봉. 2026-11 입사 → 2026년 1호봉 / 2027년 1호봉 / 2028년 2호봉. 2022-07 입사 → 2026년 5호봉(변동 없음).
- 영향 화면: 근로자 명부 목록·수정, 인사평가 목록, 인사 변동. 급여·계약서 금액을 호봉으로 자동 계산하는 곳은 없다(금액 변동 없음). 본섭 영향 인원: 2026년 입사자 3명(이한영·김영서·형일우) 2호봉 → 1호봉.
- 지시 근거: 대표님 "1~3분기에 입사했으면 내년에 2호봉이지, 올해는 1호봉이고." (내규 조항 원문은 미확인 — 코드 주석 기준 규칙)
