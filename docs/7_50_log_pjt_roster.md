# 개발로그 — 근로자 연명부(pjt_roster) 신설 v1.0.0

> 작성: 춘식이(Claude) · 2026-09-30 · 배포: portal-test (본섭 대기)

## 요청 · 결정 경과

1. 연명부 ② 착수 전 점검: ① 골격은 저장소에 없었음(이전 로컬 빌드 유실) → ①+②를 함께 구현하기로 함.
2. 대표님 요구: 공수 체크·건강검진 이력 관리 용이화. 항목 — 이름, 주민번호, 성별, 입사일, 퇴사일, 전화번호, 계좌번호, 일반/배치전 검진일, 자격인증, 사내화 교육 여부(4종), 상생협력포탈 ID/PW, 사진.
3. 교육시간·정기/특별안전교육은 추후 PJT 관리 연동으로 제외.
4. 사진: 해상도가 낮으면 쓸 수 없으므로 크기를 키우고, 화면에 바로 표시하지 않고 파일 형태로 보관 후 열어서 다운로드하는 구조.
5. 사진 한도 논의: 첫 제안(700K자·1600px)에서 950K자(≈710KB)·2000px로 상향. 900KB 파일은 base64 시 약 1.2MB가 되어 문서 한도(1MiB)를 넘으므로 불가. 실제 신분증 스캔 2장(310×209, 676×456)으로 확인 — 원본 크기 그대로 각 19KB·65KB로 저장됨.

## 설계 결정

- 컬렉션 분리: 기본정보는 기존 `master_workers`(호환 유지), 민감정보는 `master_worker_private`, 사진은 `master_worker_photos`(관리자 전용).
- 인라인 핸들러의 `form` 식별자가 `<input>.form` 속성과 충돌하는 문제를 피하려고 상태 변수명을 `wf`로 하고 `window.wf`로 노출.
- 주민번호 입력 중에는 전체 재렌더 대신 안내문만 갱신(커서/포커스 유지).
- 외국인등록번호는 체크섬 방식이 달라 검증번호 불일치 시 경고만.

## 보안규칙

- 발견: 기존 catch-all은 "승인된 직원 전원 허용"이며 Firestore 규칙은 OR 평가라 개별 match만으로는 새 컬렉션을 막지 못함 → `isAdminOnlyCollection()` 신설 후 catch-all에서 제외.
- 사진 문서: 관리자만 create/update, `dataUrl` 문자열·1,000,000자 미만·`data:image/(jpeg|png|webp);base64,` 정규식.
- 배포: 조회해 둔 기준본과 동일함을 확인 → 규칙셋 생성 → 활성화 직전 재확인 → release 갱신. 전 규칙 `df0590c0…` → 후 `32239773…`. 사본은 portal-test `backup/firestore_rules_20260930/`.
- 참고: 이 서비스 계정에는 규칙 `:test` 권한이 없어 문법 검증은 규칙셋 생성(자체 검증)으로 대체.
