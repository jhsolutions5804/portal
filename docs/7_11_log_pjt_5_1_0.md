# 7.11. 개발로그 — PJT 5.1.0 (FAB/SUP 종료·재개 확장, 종료 PJT 전용 뷰)

> 작업일: 2026-07-26 · 작성: 춘식이(Claude)

---

## 배경

5.0.0 배포 후 대표님이 본섭에서 PJT 홈을 확인하던 중, "종료된 프로젝트" 섹션에 과거 테스트로 종료 처리된 화성 17L 카드가 남아있는 것을 발견 → 완전삭제 기능 우선 추가. 이어서 "진행 중인 프로젝트(FAB/SUP)가 실제로 완결되면 워크스페이스를 어떻게 정리하면 좋을지" 질문 → 데이터 보존 관점에서 삭제보다 종료(아카이브) 방식을 제안했고, FAB/SUP는 아직 종료 기능 자체가 없다는 점(하드코딩된 고정 메뉴라서)을 짚어 "미리 만들어두자"는 지시로 이어짐.

---

## 주요 변경

### 1. 종료된 프로젝트 완전삭제 (선행 작업)
- "종료된 프로젝트" 카드에 🗑 완전삭제 버튼 추가 (관리자 전용, 확인창 2회)
- `pjt_registry` 문서만 삭제되고, 하위에 쌓인 품목·근태·공수·일정·공사일보 데이터는 보존됨(고아 데이터로 남되 화면엔 노출 안 됨)

### 2. FAB/SUP 종료·재개 지원
- `PJT_FIXED_BASE` 상수 신설 — P4 Ph2/Ph4의 원본 정의(명칭·이모지·설명·URL)를 별도 보관. 배열에서 제거돼도 재개 시 이 원본으로 정확히 복원 가능
- 상태 저장은 `pjt_settings/{key}.status`(`active`\|`ended`) 필드 사용 — 워크스페이스 앱(`pjt/`, `pjt_ph4/`) 자체는 전혀 손대지 않음, 포털 사이드바/카드 노출 여부만 제어
- `syncPjtSubtabsFromSettings()`를 확장: 기존엔 이름/설명 동기화만 했으나, 이제 상태 확인 후 종료면 목록에서 제거·활성인데 없으면 원본에서 복원(항상 월간공수 앞에 삽입)
- 카드 ⚙️ 설정 모달의 "종료" 버튼을 경량PJT 전용에서 `pjt_home`/`pjt_manday`/`pjt_ended`를 제외한 전체 PJT로 확장

### 3. "종료 PJT" 사이드바 전용 메뉴 신설
- PJT 하위 메뉴 항상 최하단(월간공수보다도 아래)에 `🗄️ 종료 PJT` 고정 항목 추가
- 클릭 시 `showPjtEndedView()` — FAB/SUP(`pjt_settings` ended) + 경량 PJT(`pjt_registry` ended)를 하나의 화면에 모아서 카드로 표시
- `pjtRegistryCard()` 함수에 `kind`(`'fixed'`\|`'light'`) 파라미터 추가 — 고정 PJT는 재개만, 경량 PJT는 재개+완전삭제 노출
- 기존 PJT 홈 하단의 "종료된 프로젝트" 섹션(`renderPjtRegistry`)은 이 전용 뷰로 완전히 이전 — 중복 표시 제거

### 4. 실수 및 수정
- 함수 삽입 과정에서 `renderPjtHomeCards` 함수 시그니처 줄을 실수로 지워 문법 오류 발생 → `node --check`로 즉시 발견, 복구
